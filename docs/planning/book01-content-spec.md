## 策划结论

第一册的核心任务不是推荐“最便宜”或“最好”的 VPS，而是帮助第一次购买服务器的读者
完成一条可以核验的路径：

```text
知道自己要买什么
→
读懂套餐与费用
→
选择服务商和地区
→
准备账户、支付与验证
→
创建 Ubuntu VPS
→
保存访问资料
→
确认服务器已经运行
→
带着完整交接信息进入第二册
```

采用“稳定知识与厂商操作分层”的写法：

- 长期稳定的概念、选择方法和安全边界构成正文骨架；
- 使用 Vultr 作为完整操作主线；
- AWS 使用 Lightsail、阿里云使用中国站 ECS，作为补充选择，不复制三套完整正文；
- 厂商按钮、套餐、价格、支付和实名信息集中标注校订日期；
- 不把临时促销、邀请码或“最佳地区”写成长期结论；
- 使用 HTML、CSS 或内联 SVG 仿真界面，不使用真实软件截图。

第一版面向中国大陆读者。涉及账户、支付、实名认证和可售地区时，必须明确适用范围，
不得把一次测试结果扩展为所有中国用户都适用。

支付失败处理、库存等待和服务商开通延迟。第一次阅读建议预留 30—60 分钟，正文必须在
封面和开始之前明确说明这一边界。

## 1. 第一册目标读者

### 核心读者

- 从未购买过 VPS 的普通用户；
- AI 工具用户、内容创作者、知识工作者、跨境从业者和小企业主；
- 希望为第二册准备一台可用服务器，但不准备先系统学习 Linux 的读者；
- 可能只使用过普通网站账户、网购和桌面软件，从未接触云服务控制台的读者；
- 可能没有海外支付经验，也不知道支付失败、预授权和实名认证分别意味着什么。

### 默认具备的能力

- 会使用浏览器；
- 会注册普通网站账户；
- 会收取电子邮件和短信；
- 会复制、粘贴并保存文字；
- 能理解账号、密码、账单和订单的基本含义。

### 默认不具备的知识

- 不知道 VPS、云服务器和虚拟机之间的关系；
- 不理解 CPU、内存、磁盘、带宽和流量；
- 不知道公网 IP、IPv4、IPv6、机房和线路是什么意思；
- 不知道 Ubuntu、root、sudo、SSH 和 SSH 密钥是什么；
- 不知道“停止服务器”“删除服务器”和“停止计费”可能不是同一件事；
- 不会判断套餐是否包含公网 IPv4；
- 不熟悉外币支付、税费、3-D Secure、预授权或身份验证流程。

### 需要主动消除的焦虑

- 害怕选错地区、系统或套餐后无法修改；
- 害怕点错按钮产生持续费用；
- 不知道价格是按小时、按月还是二者取较小值；
- 不知道支付失败是银行卡、账户还是服务商审核造成的；
- 担心实名认证信息被滥用；
- 不知道密码、私钥和服务器 IP 哪些可以公开；
- 看到服务器状态为 Pending、Installing 或 Running 时不知道该等还是该处理；
- 购买完成后仍不知道下一步应该复制哪些信息。

## 2. 阅读前提

读者开始前需要：

- 一台可以正常使用浏览器的电脑；手机可以用于阅读和验证，但不作为唯一操作设备；
- 一个长期可用、能够接收验证邮件的电子邮箱；
- 一个由读者本人控制的手机或身份验证设备；
- 一个密码管理器，或至少一个不会公开同步的安全凭证保存位置；
- 一种准备尝试的合法支付方式；具体可用方式必须按服务商和读者地区校订；
- 能够如实填写账户、账单和必要的身份验证信息；
- 已了解并愿意遵守所在地法律、服务商条款和组织安全制度；
- 一段不会被中途打断的操作时间，具体时长待完成主线服务商试走后确定。

读者不需要提前具备：

- Linux、命令行或 SSH 知识；
- 海外银行卡；
- 域名；
- Docker、Cloudflare 或代理协议知识；
- 现成的 SSH 密钥。

内容不得承诺每位读者都能使用同一种支付方式，也不得指导绕过支付、实名、风控、制裁
或地区限制。

## 3. 学习结果

### 认知结果

完成第一册后，读者应当能够：

- 用自己的话解释 VPS 是租用的远程计算资源，不是一台放在自己家里的实体电脑；
- 区分 vCPU、内存、磁盘、带宽、流量、公网 IP、地区和操作系统；
- 理解“离自己近”“延迟低”“目标服务可用”和“适合自己的用途”不是同一个判断；
- 看懂一张基础套餐卡和一张下单确认页；
- 知道持续计费、流量超额、备份、快照和公网 IPv4 可能产生额外费用；
- 知道密码、SSH 私钥和完整恢复信息属于敏感凭证；
- 知道自建 VPS 不代表匿名，也不保证任何第三方服务一定可用。

### 操作结果

完成第一册后，读者必须已经获得：

| 交付物 | 验收证据 |
| --- | --- |
| 一台正在运行的 VPS | 服务商控制台显示明确的运行状态，且不是仍在创建或已停止计费的状态 |
| 一个公网 IP | 实例详情页显示可复制的独立公网 IPv4；IPv6-only、NAT 和共享 IPv4 不通过验收 |
| 一个管理员账户 | 明确记录 `root`，或一个已知可以使用 `sudo` 提升权限的用户名 |
| 一种登录凭证 | 已安全保存登录密码，或知道与服务器匹配的 SSH 私钥存放位置 |
| 一个明确的服务器地区 | 记录城市或服务商区域代码，并知道它与账单账户地区不同 |
| 一个明确的操作系统 | 确认是本书校订版本所支持的 Ubuntu 镜像 |
| 一份安全的交接记录 | 保存非敏感实例信息，并只记录凭证存放位置，不把私钥正文抄入普通笔记 |
| 一次成功的 SSH 登录 | 在 Windows 或 macOS 上使用密码或密钥登录，执行 `whoami`，再用 `exit` 退出 |
| 第二册入口条件 | 已验证服务器可登录，并能使用交接记录在第二册重新进入服务器 |

### 整册完成条件

建议仍只把编号正式章节计入完成率；introduction、appendix 和 sources 不计入。读者只有
在最终交接清单的全部必填项完成后，才应把最后一章标记为完成。

“付款成功”不等于本书完成。“收到创建邮件”也不等于本书完成。

## 4. 不包含的内容

第一册不负责：

- 系统讲解 Linux、Shell 或服务器目录结构；
- 系统教授 SSH 配置、修改端口、代理跳板、端口转发和生产级加固；
- 安装 3X-UI、Xray、Docker、Web 面板或任何业务软件；
- 配置 VLESS、Reality、Clash Verge Rev 或 Shadowrocket；
- 购买域名、配置 DNS、Cloudflare、HTTPS 或反向代理；
- 建立完整的服务器加固方案；
- 推荐共享账户、代付渠道、来源不明的礼品卡或非官方充值方式；
- 提供规避实名认证、支付风控、服务条款或地区限制的方法；
- 承诺某个 IP 能访问特定第三方服务；
- 承诺“无限流量”“永久低价”“绝对匿名”或固定网络质量；
- 制作实时价格排行、服务商排行榜或长期有效的优惠券列表；
- 自动替读者注册账户、付款、创建或管理服务器。

账户安全、账单安全、凭证保护和必要的失败判断仍属于第一册正文，因为它们直接影响
购买是否成功。

## 6. 每章目标

### 开始之前：你最终要拿到什么

- 展示完整购买链路和最终交付物；
- 明确持续费用、实名差异、法律与服务条款边界；
- 告知读者本书不会要求其先学 Linux；
- 说明不应先注册多个账户或反复尝试支付；
- 成功状态：读者准备好邮箱、验证设备、凭证保存位置和候选支付方式；
- 失败判断：读者尚无法合法注册、无法接收验证信息，或没有可控的预算上限。

### 第 1 章：你买到的 VPS 到底是什么？

- 解释 VPS、物理服务器、虚拟化、云服务器和实例；
- 解释服务器持续运行、租用资源和管理责任；
- 区分服务商账户、服务器实例和服务器内的管理员账户；
- 说明删除数据、停止实例和停止计费需要分别确认；
- 成功状态：读者知道自己购买的是持续计费的远程计算资源；
- 失败判断：读者仍把 VPS 理解为一次性购买的软件或“自动完成所有配置”的服务。

### 第 2 章：套餐页上的 CPU、内存、带宽和流量是什么意思？

- 解释 vCPU、RAM、磁盘、SSD/NVMe、网络带宽和流量额度；
- 区分 Mbps/Gbps 的速率与 GB/TB 的流量总量；
- 解释公网 IPv4、IPv6、共享/NAT 地址和独立地址；
- 解释地区、机房、镜像、架构和计费周期；
- 说明同一个名词在不同服务商处可能有不同计费口径；
- 成功状态：读者能从套餐卡中找出计算、存储、网络、IP 和价格五类信息；
- 失败判断：页面没有说明公网 IP、流量超额或持续价格，读者不应直接下单。

### 第 3 章：先写下用途和预算，再看套餐

- 把第二册的用途转换成一张最低需求卡；
- 区分“必须有”“可以有”和“暂时不需要”的配置；
- 建立月度预算上限和可能的首笔验证金额认知；
- 解释为什么不为“以后可能用到”一次性购买过大配置；
- 记录是否必须独立公网 IPv4、Ubuntu 和兼容架构；
- 成功状态：读者在打开服务商页面前已有一张选择清单；
- 失败判断：读者只以促销价或 CPU 数量作决定。

### 第 4 章：怎样选择 VPS 服务商？

- 建立服务商评价维度：官方文档、状态页、支持渠道、账单规则、退款政策、可用地区、
  公网 IP、账户安全和使用条款；
- 区分服务商官方站点、代理销售、测评文章和返利链接；
- 说明“知名”“便宜”“线路好”都不能单独构成选择结论；
- 决定是否使用本书主线服务商；
- 成功状态：读者能说明自己选择该服务商的三项可核验原因；
- 失败判断：读者只能依据广告、邀请码或没有校订日期的价格排行。

### 第 5 章：服务器地区应该怎样选？

- 解释机房地区与账单地区、账户地区、出口 IP 地区的区别；
- 解释物理距离、延迟、网络路径和高峰期质量；
- 说明地区可用性、服务条款、数据管辖和目标服务政策可能不同；
- 给出选择流程，而不是给出永久“最佳机房”；
- 说明同一城市不同服务商、不同线路的体验也可能不同；
- 成功状态：读者记录一个首选地区和一个不可用时的备选地区；
- 失败判断：读者把某次测速或第三方服务可用性当成永久保证。

### 第 6 章：注册、支付和实名认证前要准备什么？

- 建立唯一密码和多因素认证；
- 解释账单姓名、地址、税费、支付验证、预授权和余额充值可能出现的位置；
- 说明实名认证或额外审核由服务商、支付机构和地区共同决定；
- 提供支付失败的安全判断路径，不提供绕过方法；
- 提醒不要在聊天、截图或普通笔记中保存完整银行卡和身份证件；
- 成功状态：账户由读者本人控制，联系方式可用，支付与验证资料一致；
- 失败判断：账户被锁定、验证未完成、付款反复失败或来源要求读者提供虚假资料。

### 第 7 章：使用密码还是 SSH 密钥？

- 首次解释 root、管理员用户、sudo、SSH、公钥和私钥；
- 说明密码和密钥都是登录凭证，但保存方式和登录体验不同；
- 强调私钥不能上传到教程、聊天或公开仓库；
- 解释服务商可能提供 root 密码，也可能只接受预先上传的公钥；
- 完整提供密码路径和 SSH 密钥路径，并明确推荐密钥但不隐藏密码路径；
- 在 Windows 和 macOS 上分别生成、辨认和安全保存密钥；
- 说明 Vultr SSH 公钥应在部署前加入，私钥始终只由读者保存；
- 成功状态：读者知道自己的管理员用户名、认证方式和凭证存放位置；
- 失败判断：读者只有公钥没有私钥、丢失密码，或不知道创建页面选择了哪种方式。

### 第 8 章：在创建页面逐项选择服务器

- 按真实操作顺序选择地区、套餐、Ubuntu 镜像、CPU 架构和网络；
- 确认独立公网 IP、管理员登录方式和实例名称；
- 解释备份、快照、监控、自动扩容和云防火墙等附加项；
- 不为第二册提前安装第三方应用或市场镜像；
- 不开放所有端口，也不预先安装 3X-UI；
- 成功状态：确认页显示的系统、地区、规格、IP 条件和认证方式全部符合需求卡；
- 失败判断：找不到 Ubuntu、没有明确公网 IP、选中了不兼容架构或不理解附加费用。

### 第 9 章：下单前最后核对费用

- 区分标价、持续价格、首笔扣款、账户充值、税费和流量超额；
- 解释按小时与按月的具体关系必须以服务商条款为准；
- 核对备份、公网 IPv4、快照或支持服务是否单独收费；
- 说明关机、停止、释放和删除的计费规则可能不同；
- 成功状态：读者知道首笔可能支付多少、正常每期支付多少、怎样停止后续费用；
- 失败判断：结算页总价与预期不同，或无法解释其中任何附加项。

### 第 10 章：支付后怎样确认服务器真的开通了？

- 识别创建中、运行中、失败和被暂停等状态；
- 在实例详情页找到公网 IP、地区、Ubuntu 版本、架构和默认用户名；
- 识别密码查看、重置密码、Web Console、重启、重装和删除入口；
- 解释实例邮件只是提示，控制台状态和实例详情才是主要核对位置；
- 提醒不要把带有密码或私钥的页面截图发给他人；
- 成功状态：实例处于运行状态，所有交付信息完整；
- 失败判断：长时间停留在创建中、没有公网地址、镜像不符或凭证缺失。

### 第 11 章：购买或开通失败时检查什么？

- 用“账户 → 支付 → 审核 → 套餐库存 → 创建状态 → 网络与凭证”顺序排查；
- 区分支付被拒、支付处理中、账户审核和实例创建失败；
- 处理地区售罄、套餐不可用、没有独立 IPv4 和凭证未生成；
- 说明重复付款、重复注册和提供虚假资料可能让问题扩大；
- 给出联系官方支持时可提供的非敏感信息；
- 将真正的 SSH 连接错误引导至第二册，不在本章重复完整登录教学；
- 成功状态：读者能判断问题属于哪一层，并采取一个可逆的下一步；
- 失败判断：读者只能反复付款、反复删除实例或在多个变量之间同时尝试。

### 第 12 章：完成首次 SSH 登录，进入第二册

- 创建不含明文私钥的服务器交接卡；
- 核对服务商、实例 ID、地区、公网 IP、操作系统、管理员用户名和认证方式；
- 记录云防火墙是否存在，但不预先开放第二册尚未使用的端口；
- 说明公网 IP 也是实例标识信息，但密码和私钥的敏感等级更高；
- 分别给出 Windows 与 macOS 的终端入口；
- 密码路径完成 `ssh 用户名@公网IP`、首次主机提示、密码输入和 `whoami`；
- 密钥路径完成 `ssh -i 私钥路径 用户名@公网IP`、文件选择、首次主机提示和 `whoami`；
- 两条路径都使用 `exit` 正常退出，并包含 `Permission denied`、连接超时和私钥文件路径
  错误的判断；
- 将读者明确引导至第二册“开始之前”和“登录你的第一台服务器”；
- 成功状态：至少用读者选定的一种认证方式登录成功，`whoami` 与预期管理员身份一致，
  第二册所需信息都能从交接卡或安全凭证库中找到；
- 失败判断：读者尚未实际登录，或仍不知道真实 IP、用户名、认证方式和凭证位置。
