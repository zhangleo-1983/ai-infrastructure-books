# 样章：套餐页上的 CPU、内存、带宽和流量是什么意思？

> 第一册《15分钟搞定你的VPS》第 2 章样稿
>
> 样稿日期：2026-07-27
>
> 状态：用于确认内容深度和写作方式，不是正式 MDX

这一章不会让你立刻付款。

你先要学会看懂套餐页。否则页面上数字很多，你很容易只盯着价格，或者误以为数字越大
就一定越适合自己。

本章结束时，你应该能从一张套餐卡中找出五类信息：

1. 服务器能做多少计算；
2. 同时能放多少正在使用的数据；
3. 能保存多少文件；
4. 网络一次能传多快、一个月能传多少；
5. 它有没有第二册需要的独立公网 IPv4。

## 先看一张教学套餐卡

下面不是 Vultr 当前页面的截图，也不是对当前价格的承诺。它只用来说明字段之间的
关系。

| 字段 | 教学示例 | 你现在只需要知道什么 |
| --- | --- | --- |
| 类型 | Shared CPU | CPU 资源可能与其他实例共享 |
| vCPU | 1 | 有一个虚拟处理器配额 |
| Memory | 1 GB | 运行中的系统和程序共用这部分内存 |
| Storage | 25 GB SSD | 系统、软件和数据放在这里 |
| Bandwidth | 1 Gbps | 网络连接的标称速率，不等于每秒一定达到这个速度 |
| Transfer | 1 TB / month | 每个计费周期包含的数据传输额度 |
| IPv4 | Included | 套餐包含一个公网 IPv4；仍需在实例详情页再次确认 |
| Location | Tokyo | 服务器位于东京机房 |
| Operating System | Ubuntu 24.04 LTS x64 | 本书使用的系统和 CPU 架构 |

这一页真正要做的事，不是背数字，而是把每个数字放回它负责的问题。

## vCPU：服务器用来“算”的部分

CPU 是中央处理器，负责执行程序指令。套餐页常写的 vCPU，是 virtual CPU，也就是
分配给这台虚拟服务器的处理器资源。

### 1 vCPU 不一定等于独占一个物理核心

本书主线选择的是 Shared CPU，也就是共享 CPU。服务商会把一台物理服务器的计算能力
分给多台 VPS。

这意味着：

- 1 vCPU 能让 Ubuntu 和普通轻量服务正常运行；
- 它不代表你独占一颗完整的物理 CPU；
- 同一个套餐在不同时间的短时性能可能有差异；
- 视频编码、大模型推理和高并发数据库不是这一配置的目标。

第一册和第二册的主线任务是购买服务器、SSH 登录和运行轻量的 3X-UI/Xray 服务，不是
在服务器上训练 AI 模型。因此第一版把 1 vCPU 作为配置下限。

### 什么时候不应该选它

如果购买页面写的是 GPU、Dedicated CPU、CPU Optimized 或 Bare Metal，先停下来。
这些产品可能适合更重的任务，但不是本书的 15 分钟主线。

成功判断：

- 你选择的是 Cloud Compute 一类的普通虚拟机；
- 配置不少于 1 vCPU；
- 没有因为“性能更高”误选价格明显更高的专用产品。

失败判断：

- 页面只显示产品宣传语，看不到实际 vCPU 数量；
- 你选中了 GPU 或裸金属服务器；
- 你无法解释为什么需要比 1 vCPU 更大的配置。

## 内存：程序正在使用的工作台

内存通常写作 RAM 或 Memory。它保存操作系统和程序当前正在使用的数据。

可以把磁盘想成储物柜，把内存想成工作台：

- 储物柜大，表示能长期保存更多东西；
- 工作台大，表示可以同时摊开更多正在处理的东西；
- 关机后，普通内存里的临时内容不会像磁盘文件那样保留。

Ubuntu 本身、SSH、3X-UI 和 Xray 都会使用内存。内存不足时，程序可能被系统终止，
安装过程也可能异常变慢。

本书选择不低于 1 GB RAM。512 MB 套餐即使价格更低，也不进入第一版主线，因为它会
让系统更新、安装和排错留下更小余量。

成功判断：

- 套餐明确写着 1 GB RAM 或更多；
- 你没有把 1 GB RAM 与 1 GB 磁盘混为一谈。

失败判断：

- 套餐只有 512 MB；
- 页面使用 MiB，而你没有确认它与 GB 的数量级；
- 你计划在同一台服务器继续安装很多服务，却仍按本书最低配置购买。

## 磁盘：系统、软件和数据长期放在哪里

套餐页可能写 Storage、Disk、SSD 或 NVMe。

它们都在描述服务器的持久存储。Ubuntu 系统、软件包、日志、3X-UI 数据库和以后产生的
配置文件会放在这里。

SSD 和 NVMe 都是固态存储相关的名称。NVMe 通常代表一种更高速的存储接口，但对第一、
二册的轻量任务来说，容量和可靠使用比追逐最高跑分更重要。

第一版选择不低于 25 GB 系统盘。

### 磁盘可以随时缩小吗？

不要这样假设。

云服务常允许升级到更大的磁盘，但不一定允许直接缩小。购买前把“以后可以降回去”
当作承诺，会让你在选错套餐后难以恢复。

成功判断：

- 系统盘不低于 25 GB；
- 你知道自动备份和快照不是磁盘容量本身；
- 你没有额外购买本书不需要的块存储。

失败判断：

- 页面只显示“高速 SSD”，却没有写容量；
- 你另外添加了一个收费磁盘，但不知道它将用来存什么；
- 你把 Snapshot 当成免费的永久备份。

## 带宽和流量：一个是速度，一个是总量

这是套餐页最容易混淆的一组词。

### Bandwidth：传输速率

带宽通常用 Mbps 或 Gbps 表示，描述网络连接在理想条件下单位时间能传输多少数据。

这里的小写 `b` 是 bit，也就是“比特”：

```text
8 bit = 1 byte
```

因此，1 Gbps 的理论换算上限约为 125 MB/s。但真实速度还会受到服务商共享资源、网络
路径、距离、拥塞、对端速度和协议开销影响。

看到 1 Gbps，不应理解成“任何时候下载都能达到 125 MB/s”。

### Transfer：计费周期内的数据量

流量额度通常用 GB 或 TB 表示，描述一个计费周期内可以传输多少数据。

它像手机套餐里的月流量：

- 1 Gbps 回答“这条路标称能跑多快”；
- 1 TB 回答“这个月套餐包含多少传输量”。

不同服务商对入站、出站和超额流量的计算方式并不完全相同。不能把 AWS、Vultr 或
阿里云的一条规则直接套到另一家。

在 Vultr 主线中，正式正文需要引导读者进入 Billing 或 Bandwidth Usage 页面，确认：

- 当前套餐包含多少流量；
- 计费周期从什么时候开始；
- 哪个方向的流量计入；
- 超额后是收费、限速还是暂停；
- 当前官方超额单价和校订日期。

成功判断：

- 你能指出带宽的单位是 Mbps/Gbps；
- 你能指出流量额度的单位是 GB/TB；
- 你不会用一次测速结果推断整个月的网络质量。

失败判断：

- 把 1 Gbps 当成 1 GB 月流量；
- 页面没有说明超额处理方式；
- 因为写着“High Performance”就认为网络永远没有拥塞。

## 公网 IPv4：第二册必须拿到的地址

IP 地址用于在网络中找到设备。第一版强制要求一个独立公网 IPv4。

它应该像下面这样显示在实例详情页：

```text
203.0.113.10
```

这是文档保留地址，不是真实服务器，不能照抄。

### 为什么不能只看到“有网络”就算通过

套餐可能提供：

- 独立公网 IPv4；
- 只有 IPv6；
- 位于 NAT 后面的共享 IPv4；
- 只有私网地址；
- 需要另行购买或分配的公网地址。

这些方案都可能让实例访问网络，但第二册当前使用 `ssh 用户名@IPv4`，并围绕 VPS 公网
IP 配置和验证连接。因此主线不接受 IPv6-only、NAT VPS 或共享 IPv4。

你需要检查两次：

1. 下单前，套餐或结算页明确包含公网 IPv4；
2. 开通后，实例详情页确实显示一个公网 IPv4。

成功判断：

- 购买页明确说明公网 IPv4；
- 实例创建后得到可复制的 IPv4；
- 地址不是 `10.x.x.x`、`172.16.x.x—172.31.x.x` 或 `192.168.x.x` 这类常见私网地址。

失败判断：

- 页面只写 IPv6；
- 需要端口映射才能从公网连接；
- 只看到 VPC 内网地址；
- 公网 IPv4 是额外收费项，但结算页没有计入预算。

## 地区、系统和架构也属于套餐选择

资源数字正确，不代表整台服务器已经选对。

第一版主线还要同时满足：

| 项目 | 主线要求 | 为什么 |
| --- | --- | --- |
| 地区 | 东京演示，洛杉矶备选 | 形成统一操作路径；不承诺网络效果 |
| 系统 | Ubuntu 24.04 LTS | 与第二册现有命令和验收环境一致 |
| 架构 | x86_64 / amd64 | 减少安装包和命令分支 |
| 镜像类型 | 纯操作系统 | 不预装 WordPress、Docker 或第三方面板 |

Ubuntu 26.04 LTS 已经发布，不代表本书必须立刻追新。24.04 LTS 仍处于标准支持期，而且
第二册已经使用该版本完成回归，所以第一版先保持一致。

3X-UI 官方项目也支持 arm64。这里选择 amd64 不是因为 arm64“一定不能用”，而是为了
让零基础主线只保留一个已经核对的架构。

## 用 60 秒检查一张套餐卡

打开真实购买页面后，按下面顺序读，不要先点击 Deploy：

1. 找到产品类型，确认是普通 Shared CPU 云服务器；
2. 找到 vCPU、RAM 和系统盘；
3. 找到带宽速率和月流量额度；
4. 找到公网 IPv4 是否包含；
5. 找到地区、Ubuntu 版本和 CPU 架构；
6. 找到持续价格和可能的附加项；
7. 把看不懂或没写清的字段记录下来，不凭猜测继续。

### 本章检查表

- [ ] 我能区分 vCPU、RAM 和磁盘；
- [ ] 我能区分带宽速率和月流量；
- [ ] 我知道“共享 CPU”不等于独占物理核心；
- [ ] 我选择的套餐不低于 1 vCPU、1 GB RAM 和 25 GB 系统盘；
- [ ] 我已经找到独立公网 IPv4，而不是只看到 IPv6 或私网地址；
- [ ] 我选择 Ubuntu 24.04 LTS 和 amd64；
- [ ] 我没有因为促销或更大的数字加入不需要的产品。

全部勾选后，你才适合进入下一章，用需求卡和预算判断这个套餐是否值得购买。
