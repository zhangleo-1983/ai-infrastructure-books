## 这份台账解决什么问题

这份台账用于在一台隔离的 Ubuntu VPS 上，按书中顺序验证命令、输出、对象状态和章节之间
的连续性。2026-08-11 已完成开始检查和第 3—12 章连续执行；本记录不等于第三册已经通过
搜索、打印、跨浏览器和发布候选验收。

验证必须使用专门用于教学的 VPS。不要在承载第二册网络服务、网站、数据库或其他真实业务的
服务器上直接照做。验证人员应逐章填写结果；未填写的项目一律视为未验证。

## 开始前的统一停止条件

出现以下任一情况，停止执行并把本次结果记为“安全停止”：

1. 服务器上已有无法确认用途的容器、端口、volume、目录或系统服务；
2. 没有第二个已经验证可登录的 SSH 会话；
3. 操作系统不是 Ubuntu 24.04 LTS，或 CPU 架构不是 `amd64`；
4. 内存、磁盘或网络状态不足以完成练习；
5. 当前服务器承载真实业务，且没有经过授权的隔离方案；
6. 实际命令的作用范围比正文描述更大，或目标名称与台账不一致；
7. 第 11 章的备份归档不可读，或恢复验证没有通过；
8. 需要通过 `docker system prune`、`docker volume prune`、`docker compose down -v`
   或不明来源脚本才能继续。

## 证据与结果分类

每个验证点只记录经过脱敏的必要证据，例如命令退出状态、对象名称、状态词和关键错误行。
不要为了证明成功而保存真实公网地址或凭证。

结果统一使用以下五类：

- **通过**：实际行为、成功状态和结束状态与正文一致；
- **文档差异**：功能正确，但版本输出、提示语或显示顺序发生非实质变化；
- **命令纠错**：正文命令本身需要修改；
- **安全停止**：继续执行可能影响已有服务、数据或访问入口；
- **环境阻塞**：网络、配额、架构或云平台限制导致无法完成。

## 第 6 章公网演示决策点

当前草稿的默认验证路径是：

1. 容器端口只绑定 `127.0.0.1`；
2. 在服务器本机使用 curl 验证；
3. 在读者电脑上通过 SSH 本地端口转发查看；
4. 删除教学容器并确认 TCP 8080 已释放。

这条路径不需要开放云防火墙或 UFW，也不要求把无鉴权页面暴露到公网。实机验证时应按这条
路径执行。

如果作者以后决定加入“受控公网演示”，必须另行确认：

- 使用哪一条临时防火墙规则；
- 允许访问的来源地址；
- 演示开始前和结束后的精确规则状态；
- 谁负责在失败时关闭入口；
- 页面是否需要鉴权。

没有这些决定时，不得在验证现场临时发明公网开放步骤。

## 已解决的连续性观察项

实测原命令 `sudo docker run hello-world` 会留下一个名称随机的 Exited 容器，而第 4、5 章只
清理具名对象。这会让第 12 章“没有遗留练习对象”的目标与实际状态不完全一致。

本轮采用以下最小修正：

1. 第 3 章安装验证改为 `sudo docker run --rm hello-world`；
2. `--rm` 只作用于当前临时验证容器，不会扩大删除范围；
3. 第 4 章继续用 `book03-hello` 展示可保留的 Exited 容器，第 5 章按明确名称删除；
4. 实测遗留对象已在确认镜像、状态和退出码后定向删除，没有使用 prune；
5. 第 12 章最终 `docker ps -a` 只剩主 Compose service。

这项修正保留了生命周期教学，同时让整册对象收尾可重复、可核对。
