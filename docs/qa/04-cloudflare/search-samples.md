## 后续 RC 的复核方法

1. 运行 production build，让 Pagefind 重新生成静态索引；
2. 运行 `tests/e2e/search-quality.spec.ts` 的 Chromium 项目；
3. 每个查询观察前五条结果，并核对章节和正文锚点；
4. 确认第四册打印页、目录页和其他重复正文没有进入索引；
5. 若正文、标题或 Pagefind 版本变化，重新记录实际结果；
6. 无法通过静态配置消除的中文分词边界应明确记录，不为单个查询引入后端搜索服务。

当前结论：搜索质量满足 RC 使用要求；`Quick Scan` 是已知非阻塞边界，不应表述为已经命中。
