## 不阻塞当前 RC 的边界

以下项目用于提高下一版对厂商实时状态的置信度，不代表当前已经发现故障。真实账户
部署前主线已经完成；剩余项目是可选持续 QA：

- 中国大陆不同地区、运营商和时段的普通浏览器访问差异；
- 其他账户可能出现的支付方式、额外审核和 KYC 分支；
- 东京、洛杉矶的实时库存、价格和 Looking Glass 表现；
- Vultr 后续创建页面的字段名称、默认值和排列变化；
- 真实实例中的密码、SSH 密钥、账单和销毁闭环。

Vultr Status 曾对非浏览器自动链接请求返回 403。该结果只能说明自动请求可能受到
访问策略限制，不能推断中国大陆家庭宽带会返回 403，也不构成当前版本的发布阻塞。

如果真实测试或稳定读者反馈表明注册、官方支付、独立公网 IPv4、Ubuntu x64、
密码登录或 SSH 密钥登录中的任一主线无法完成，应立即把对应问题升级为阻塞问题。

## 安全与隐私边界

- 仓库中不得写入真实 IP、密码、SSH 私钥、支付记录、Cookie 或身份材料；
- 内部实测截图不得直接用于公开图书；
- 不使用共享账户、代付、推广返利、破解软件或非官方充值渠道；
- 价格、库存、支付和审核结果以读者本人账户当前页面及官方支持回复为准。

## 进入正式版的建议

`rc.2` 已吸收 2026-07-28 的部署前现场差异并完成自动回归。进入 `v1.0.0` 前建议：

1. 由作者通读本轮修订，确认术语、风险提示和产品口径；
2. 邀请少量目标读者试读购买前流程，记录无法理解或找不到字段的位置；
3. 若要提供独立下载 PDF，基于 `rc.2` 重新生成并做分页抽查；
4. 决定正式托管平台和域名后，完成一次带 base path、canonical 和 Pagefind 的部署预演；
5. 发布前再次运行 `npm ci`、`npm audit`、`npm run check:all` 和 `git diff --check`。

创建一台合法测试实例、在 Windows/macOS 复核登录、核对账单并销毁资源，仍然有助于
持续提高置信度，但不是当前教学仿真版 `rc.2` 或正式版的强制发布条件。
