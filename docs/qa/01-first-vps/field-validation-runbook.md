## 目标

使用一个由项目 Owner 本人控制的合法测试账户，验证：

1. 第一册从访问服务商、账户安全、支付验证到 Deploy 前最终摘要的完整主线；
2. Shared CPU、地区、套餐、Ubuntu、Public IPv4、认证、防火墙和附加项能够按正文完成；
3. 价格、库存、支付和控制台变化能够被识别并记录，而不写成长期承诺；
4. 真实部署、SSH、第二册端到端与销毁闭环是否必须成为发布门槛。

本轮不以收集账户截图为目标，不把真实凭证、支付记录或身份材料写入仓库。

项目 Owner 于 2026-07-28 确认：实例状态、凭证、SSH、第二册衔接和销毁流程可以依据
官方资料、标准 OpenSSH 行为、教学仿真与自动回归维护，不要求为内容发布强制产生费用。
因此前三段属于本轮验收范围并已完成；第四至第六段保留为可选持续 QA。

## 操作边界

项目 Owner 必须亲自完成：

- Cloudflare 安全验证或 CAPTCHA；
- 账户注册、登录、密码、验证码和两因素认证；
- 支付方式、账单地址和可能的身份验证；
- 最终 Deploy 或其他会产生费用的确认；
- Destroy 及其他删除资源的最终确认。

可由协作流程检查：

- 页面字段名称、默认值、排列和说明；
- 方案、地区、系统、架构、公网 IPv4、防火墙和备份选项；
- 不含敏感值的成功状态与错误类型；
- SSH 命令结构、终端提示和章节衔接；
- 资源销毁后列表及账单中是否仍有活动项目。

## 禁止记录

- 账户邮箱、手机号、真实姓名和账单地址；
- 卡号、支付账号、订单号、发票号和交易截图；
- CAPTCHA、验证码、恢复码和身份材料；
- 真实公网 IP、实例 ID、主机名和控制台 URL；
- 密码、私钥、公钥全文、Cookie、API Key 和订阅 URL；
- 未经脱敏的浏览器截图或终端日志。

只允许记录“成功 / 失败 / 未出现 / 条件出现”、字段标签、公开套餐信息、系统版本、
地区名称、错误类别和经过概括的差异。

部署页的默认值存在明显误购风险：首次进入时默认产品为 Dedicated CPU，默认地区为
Chicago，默认选中的套餐远高于本书需求；进入软件配置后默认镜像为 Ubuntu 26.04 LTS
x64，Automatic Backups 默认开启。以上均只记录 2026-07-28 当前界面事实，不应写成
长期不变的固定默认值。

支付方式绑定后，Beta 页的 Regular Cloud Compute 档在 Tokyo、Seoul、Los Angeles
等测试地区仍重复显示“套餐在此地点不可用”。官方旧版部署页却能在 Tokyo 的 Shared
CPU 高性能档继续选择系统，并在选择镜像后启用 Deploy 按钮。因此，当前更准确的结论
是“Beta 页对部分套餐的可用性展示与旧版流程不一致”，而不是账户没有部署资格，也
不是中国大陆访问限制。发布前仍应以最终 Deploy 摘要和实际创建结果为准。

Firewall Group 创建流程已验证为 Network / Firewall Groups / Create Firewall Group。
当前界面添加入站 IPv4 规则时可直接选 SSH 预设，端口会锁定为 22；来源限制需要使用
Custom 手工填写可信 IPv4 CIDR。台账与仓库不保存真实来源地址。创建页没有出现
Firewall Group 字段的判断只适用于 Beta 页；旧版创建页会显示 Firewall Group 下拉，
并已成功选择测试组。因此正文需要说明 Beta 与旧版路径差异，不能笼统写成所有创建页
都没有绑定入口。

## 修订判定

每个差异按以下类别记录：

- `技术纠错`：当前步骤不能完成或结论明显错误；
- `安全纠错`：正文可能诱导泄露凭证、重复扣费或误删资源；
- `界面差异`：字段名称、排列或状态文字变化，但主线仍成立；
- `账户差异`：支付、审核、KYC、库存或地区条件导致；
- `无需修改`：仿真界面已经正确表达关系，不需要追随像素或小文案变化。

未经项目 Owner 确认时，只有技术纠错和安全纠错可以直接进入正文修订，其他变化先
形成建议。本轮的界面差异、账户差异和结构调整已由项目 Owner 确认实施，并逐项记录在
`field-validation-revisions.md`。
