  ## 第一步：记录现在的状态，不把阅读完成当作部署完成

  在自己的电脑打开第八章评估记录、第九章入口记录、第十一章恢复记录，把有证据的项目写入交接卡。
  没部署过就写“未部署”；恢复环境只做过断网读写，就写“同版本离线读写，模型生成未覆盖”。
  维护基线是最近一次确认正常的状态，包含日期与版本，不是一组永远有效的默认值。

  在 VPS 的 SSH 管理终端逐行运行下面的只读检查。第一行失败就停止，pwd 必须是第三章原项目目录。
  config -q 只检查配置是否能解析，不输出展开后的秘密，也不证明所有端口正确。

  <CodeBlock label="VPS 原项目：状态、端口和资源基线" code={baseline} />

  对照第三章：常驻服务应保持正常，init_permissions 退出 0 可以是正常初始化结果；
  主机只发布 nginx 的回环 8088，不应多出数据库或插件调试端口。
  再经已验证的入口查看原应用、三份资料与已发布版本，不例行运行模型来证明网页健康。

  <strong>成功状态：</strong>状态、版本、端口、数据与费用都能对应最近一次记录。
  <strong>失败判断：</strong>出现陌生成员、未计划更新、意外公网端口或持续未知用量；转第十章定位，停止新的运行。
</section>

<section className="book-section" id="book06-12-cadence">
  ## 第二步：给资料、日志和备份安排保留期限

  教学实例运行期间，每次练习前后看模型用量和后台任务；长期保留时，至少每周核对磁盘、服务与备份，
  每月核对账单、成员、插件版本及域名到期时间。这个节奏是作者建议，临近费用或磁盘停止线时应提前检查。
  一次只改一项；涉及更新先回第十一章，不把巡检变成自动拉取最新镜像。

  <ComparisonTable>

  | 对象 | 在哪里核对 | 保留与清理原则 |
  | --- | --- | --- |
  | 工作流运行记录 | Dify 原应用的 Logs / 运行历史 | 保留评估所需的脱敏结论；原问题、候选片段和输出可能仍在数据库 |
  | 容器日志 | 第十章有限 logs 命令、VPS 磁盘 | 每次只看相关服务与时间段；行数限制不等于内容已脱敏 |
  | TXT 与知识库 | 本地文件、Knowledge 文档及片段 | 停用文档只改变可用状态，不删除历史回答、下载或备份 |
  | DSL 与导入副本 | 受控下载目录、Studio | 标明日期和“仅检查”用途；原始 DSL 不公开，副本也可能连接同一知识库 |

  | 七文件备份与其他副本 | VPS 备份目录、电脑、快照或同步存储 | 标明唯一可用恢复点和到期日；删除前先确认是否仍需恢复 |

  </ComparisonTable>

  在本地记录每类材料的用途、保管人、预计删除日期和最近复核日期。不需要长期保留的实验，优先在约定日期整套退役。
  本书不假设 Dify 自动按某个天数清除所有记录；界面没有已核对的清理功能时，不直接改数据库表或清空 Redis。
  若要长期服务，需要另行验证日志轮转、容量上限和备份保留策略；`--tail 80` 只限制这次显示，不限制存储增长。

  <strong>成功状态：</strong>每份副本都有用途和到期责任，空间能容纳运行与恢复。
  <strong>失败判断：</strong>唯一备份即将随 VPS 删除，或恢复副本无人负责；先补记录和受控副本，再继续。
</section>

<section className="book-section" id="book06-12-app">
  ## 第三步：只停一个应用，先关它的入口

  只想暂停“虚构活动常见问题助手”时，不应停止整套 Dify 或撤销被其他应用使用的模型连接。
  在 Studio 打开已核对的原应用，进入发布/访问入口管理区，找到内置 Web App 卡片及其启用开关。
  固定 1.17.1 源码有独立的 Web App 启用状态；实际导航与中文名称须以本机版本核对，找不到对应卡片就先停，
  不把“重新生成访问链接”“删除应用”当暂停按钮。
  [固定版本入口卡片](https://raw.githubusercontent.com/langgenius/dify/1.17.1/web/app/components/app/access-point/built-in-access-points/web-app-card.tsx)

  先确认没有在途运行，记录开关原状态，再关闭 Web App，等待保存完成并刷新确认。
  用原来的应用链接重新加载页面，预期不能再使用该网页入口；只做页面访问，不提交测试问题。
  原应用仍应在 Studio，画布和资料连接保留。

  <MockWindow title="单应用暂停要检查的三件事：教学仿真">
    <div className="mock-form-grid">
      <MockField label="网页入口">关闭后刷新，旧链接不能继续进入可用应用</MockField>
      <MockField label="应用定义">仍在 Studio；没有删除画布、日志或知识库</MockField>
      <MockField label="其他调用">调试、API、后台任务分别核对，不能由网页开关推定</MockField>
      <MockField label="恢复条件">确认费用与访问保护，再重新启用原入口</MockField>
    </div>
  </MockWindow>

  Web App 开关不等于关闭服务 API，也不禁止管理员从画布调试；已经开始的远程请求可能继续计费。
  本册没有创建 Dify 服务 API key、外部调用者或定时任务。实际存在这些扩展时，先盘点并逐一停止，
  不能把本节的网页检查写成“所有调用已停”。需要立即停止整个教学实例时，使用下一节。

  第八章的“导入检查－虚构活动”如果不再需要，在 Studio 先打开它核对描述和画布，再返回该卡片菜单，
  选择 Delete（删除），看清确认对象后完成删除。原应用必须仍在；不要删除被原应用引用的知识库。
  删除应用是永久动作，DSL 不含运行日志，也不能恢复所有历史。
  [官方应用管理](https://docs.dify.ai/en/self-host/use-dify/workspace/app-management)

  <strong>成功状态：</strong>暂停范围明确且可恢复，或者只删除已确认不再保留的检查副本。
  <strong>失败判断：</strong>状态刷新后又开启、旧入口仍可用、误选原应用；保持外部入口撤下，保留数据并查原因。
</section>

<section className="book-section" id="book06-12-pause">
  ## 第四步：整套暂停，保留数据和 Access

  在第九章的 Cloudflare Tunnel 详情中找到本次主机名对应的 published application route，核对目标仍是回环 8088。
  需要临时下线时先移除这一条 route，并在 DNS 页面确认对应教学记录的实际状态；若自动记录未移除，
  核对名称、类型与目标后只移除该条。不要删根 zone、nameserver 或 DNSSEC，也不要先删除 Access 应用。
  随后确认公开入口已无法到达 Dify；旧 DNS 缓存可能存在，不能只凭自己电脑的一次结果判定所有网络已更新。

  正常维护先等运行和索引任务结束，再在原项目目录停止全栈。恢复副本若仍运行，按第十一章的 d6r 定义另行 stop，
  不把原项目停止当作恢复副本也已停止。

  <CodeBlock label="VPS 原项目：暂停全栈，不删除容器或数据" code={stopStack} />

  第二条命令应无运行容器输出。回环 8088 应不再提供应用；用第十章本机检查确认。
  异常强制退出不是正常备份条件，要按第十一章处理后才能制作一致归档。
  [Docker stop](https://docs.docker.com/reference/cli/docker/compose/stop/)

  如出现未知调用或凭证泄漏，优先在提供方撤销专用 key，并尽快停止相关实例，不必为了等正常任务而放任费用增长。
  这种紧急停止与正常停写备份不同，要记录中断影响。撤销 key 不会退回已经发生的费用，也未必立即终止正在生成的请求。

  临时暂停后 VPS、快照、备份、域名和其他订阅仍须核账。要恢复时先确认异常已排除、配置未变、恢复副本仍停着，
  再启动原有容器；下面的 start 不读取新的 .env。如果已经改了配置或删除容器，应返回第三、九或十一章的对应流程。

  <CodeBlock label="VPS 原项目：恢复已有容器并检查状态" code={startStack} />

  从已验证的入口检查数据与版本。若当前配置仍是 HTTPS，不能把 localhost 页面打不开直接判成数据损坏；
  SSH 本地回退应按第九章恢复已保存的本地地址配置，再验证。重新建立 route 前必须先确认全主机名 Access 与源站校验。
  单纯暂停不需要补发模型请求；如要复测生成，按第八章另计一次预算。
</section>

<section className="book-section" id="book06-12-secrets">
  ## 第五步：分清凭证，撤销时不要改错对象

  <ComparisonTable>

  | 凭证 | 作用与位置 | 撤销/变更后要验证什么 |
  | --- | --- | --- |
  | 模型提供方 API key | 提供方控制台管理，Dify 模型连接使用 | 本次专用 key 已撤销或删除，旧调用来源停止；不新建请求来“试扣费” |
  | Dify 管理员密码/会话 | Dify 管理入口 | 修改与退出会话属于账户操作，不会撤销模型 key 或 Cloudflare 身份 |
  | Access 会话 | 主机名前的身份检查 | 删除不应继续允许的身份规则后，再撤销本应用已有会话；仅撤会话仍可能重新登录 |
  | Tunnel token | connector 接入专用 Tunnel | 属于连接凭证，不是 Dify 密码；撤销/删除通道前确认没有其他 route 或 connector |
  | .env 内部秘密 | 应用签名、服务之间认证及数据解密相关材料 | 需要配套变更和完整恢复方案；不能重跑 prepare-env.py 当“轮换所有密码” |
  | 备份里的历史凭证 | 归档和恢复副本也持有秘密 | 撤销提供方 key 后旧备份中的值仍是敏感材料；不得用旧备份重新启用已退役凭证 |

  </ComparisonTable>

  模型 key 在提供方控制台的 API keys 页面处理：用受控记录辨认本次专用条目，核对用途，选择撤销/删除并确认。
  回到列表确认状态，记下时间和最终用量；不要把完整 key 复制出来对比。不能辨认或与其他业务共用时先停，
  应重新规划共用方迁移，不能为结束本书练习一并撤销它们。

  Access 的应用级会话撤销入口在 Access controls → Applications → 本次应用 → Configure → Revoke existing tokens。
  先核对策略中的身份范围；会话撤销不会自动移除 Allow 规则。不要为本次实验执行账户全部用户的全局撤销。
  [Cloudflare 会话管理](https://developers.cloudflare.com/cloudflare-one/access-controls/access-settings/session-management/)

  定期轮换不是把每个秘密改成同一个新值。普通模型 key 更换按第四章重新核对连接、验证费用与节点参数；
  内部数据库密码和加密材料另需经过验证的变更步骤。本册没有完成内部秘密轮换演练，不能给出“随便改完重启”的方法。
</section>

  | VPS 备份与镜像包 | $HOME/book06-backups 下本次日期目录 | 和运行数据不同；留存/销毁决定逐包记录 |
  | 电脑的下载、DSL、TXT、备份 | 本人受控保存位置及同步副本 | 需要保留的移入受控存储并登记期限；不要误删别册材料 |
  | 云快照、自动备份、附加磁盘 | VPS 服务商各自资源列表 | 不假定实例销毁会连带删除或停止收费 |

  </ComparisonTable>

  本章采用“结束专用 VPS”的完整退役分支，不提供抹除共用主机目录的一行命令。
  如果决定保留 VPS，只删除 Dify 数据，停在有明确剩余清单的状态，另做逐路径方案；不能填写“数据已清空”。

  ## 第七步：最后处理通道、计算资源和四笔账

  预期 ActiveState=inactive、UnitFileState=disabled。unit 不存在或状态异常时停在核对安装方式，
  不临时装一份服务来完成清理。在控制台确认 connector 不再连接，再删除专用 Tunnel。
  遇到仍有活动连接的提示先查连接来源，不强制移除未知连接。最后才删除不再服务任何入口的本次 Access 应用。

  在自己的电脑把本次不保留的原始 DSL、归档和下载从精确目录删除，再检查废纸篓/回收站及已知同步副本。

  只保留脱敏结果和已明确继续保管的资料，记录它们的位置指针与期限，不在交接卡附带原始秘密。
