  ## 开始前：先确认你接过来的是什么

  工作流（Workflow）把一次任务拆成节点，变量负责把数据传给下一步。知识库负责存放可检索资料，
  大语言模型（LLM）负责生成文字。我们把这三件事接起来，但不把上传资料当成训练模型。

      <MockField label="模型">一个已验证的文本模型；已核对费用与停止线</MockField>
      <MockField label="运行范围">本人手动、单次运行；无循环、批量、工具或自动重试</MockField>
    </div>
  </MockWindow>

  在 Dify 的 Studio（应用工作区）打开自己的练习 Workflow，再进入画布。先核对名称和类型，
  避免改到其他应用。保留第 5 章最小流程的版本记录；本章只在草稿画布上编辑，不点击 Publish（发布）。
  如果画布只有聊天回答节点、没有自定义 question 输入，应先返回第 5 章核对应用类型。

<section className="book-section" id="book06-07-map">
  ## 第一步：先看两条路径，再改连线

  <DifyWorkflowMap />

  原来的最小流程会把任何问题直接送给模型。现在要先检索，再判断结果是不是空的。
  空结果走固定提示；有候选片段才允许进入生成节点。候选只是“检索找到的材料”，不是答案正确性的证明。

  在画布上选中 User Input 到 LLM 的旧连线，删除这条连线；保留两个节点。删除连线不是删除节点、
  模型配置或资料。然后在 User Input 后点添加节点，选择 Knowledge Retrieval（知识检索），
  将它命名为“查活动资料”。从该节点后添加 If-Else（条件分支），命名为“有资料吗”。

  <strong>成功状态：</strong>从输入节点向右只能先走到检索，再到条件节点。<strong>失败判断：</strong>仍有一条输入直达 LLM
  的线，或者 LLM 与空提示并行执行；此时不要试跑，先删除绕开判断的旧线。
</section>

<section className="book-section" id="book06-07-retrieval">
  ## 第二步：让检索节点收到问题

  选中“查活动资料”，在右侧设置面板选择第 6 章建立的合成知识库。Query Text（查询文字）决定用
  哪段文字查资料：打开字段旁的变量选择器，展开 User Input，选择 question。选择后应出现变量标签，
  不是你手工敲进去的一串 `User Input.question`。

  <MockWindow title="查活动资料：字段绑定教学仿真">
    <div className="mock-form-grid">
      <MockField label="知识库">虚构活动规则－练习版 1</MockField>
      <MockField label="Query Text">变量标签：User Input → question</MockField>
      <MockField label="索引路线">沿用第 6 章经济索引；不切换 High Quality</MockField>
      <MockField label="输出 result">片段数组：每一项包含内容、标题等信息</MockField>
    </div>
  </MockWindow>

  数组是按顺序放在一起的一组数据。`result` 是检索节点返回的片段数组；`[]` 表示里面没有任何项。
  Workflow 必须选本应用的自定义输入变量，不能照抄 Chatflow 的内置问题字段。
  经济索引用关键词查找；本章不加 Rerank（候选重排模型），也不靠启用另一项收费服务修补匹配结果。
  [官方检索节点说明](https://docs.dify.ai/en/self-host/use-dify/nodes/knowledge-retrieval)

  <strong>成功状态：</strong>节点显示正确知识库与 question 标签，预期输出类型为片段数组。
  <strong>失败判断：</strong>变量为空、选成文件输入、知识库不可选或类型报错；回到前置卡处理，不直接把问题接回模型。
</section>

<section className="book-section" id="book06-07-empty">
  ## 第三步：空结果直接给提示

  选中“有资料吗”，在 IF（满足条件时）添加一个条件：变量选“查活动资料 → result”，运算选
  Is empty（为空）。这里不需要在右侧输入文字 `[]`；我们判断数组是否为空，不是在比较两个字符串。
  ELSE（其他情况）就是有候选片段的路径。本章不加 ELIF（额外条件）。
  [官方条件分支说明](https://docs.dify.ai/en/self-host/use-dify/nodes/ifelse)

  从 IF 出口添加 Template（模板）节点，命名为“没有资料的提示”。模板只按规则组织文字，不调用
  生成模型。本节点不用输入变量，在模板编辑区粘贴下面的固定内容。

  <CodeBlock label="粘贴到“没有资料的提示”的模板编辑区" code={noResult} />

  从这个模板后添加 Output（输出）节点，命名为“返回未找到”。输出变量名称填 `notice`，
  值通过选择器选“没有资料的提示 → output”。notice 是给结果字段起的名字，output 是模板实际生成的文字。

  <strong>成功状态：</strong>IF 这条线只经过固定模板和输出，碰不到 LLM。<strong>失败判断：</strong>result 的类型不是数组、
  当前界面不提供相应空判断，或输出值是字面量 `output`；先核对版本与变量绑定，不凭猜测替换运算符。
</section>

<section className="book-section" id="book06-07-context">
  ## 第四步：有候选片段，才交给模型

  把 ELSE 出口连到原来的 LLM 节点，将节点命名为“根据资料回答”。保留已经核验的单个文本模型、
  输出长度与费用设置，不临时换模型。若设置里有失败重试，本练习保持关闭，先让一次运行对应一次明确请求。

  在 LLM 的 Context（上下文资料）字段，通过选择器绑定“查活动资料 → result”。然后打开 System
  （系统提示词）编辑区，粘贴以下文字。最后把最末行方括号提示整行删除，通过变量选择器插入 Context
  标签。这个动作告诉模型“资料放在这里”；仅填写上面的 Context 字段还不等于提示词已经引用了它。

  <CodeBlock label="系统提示词草稿：最后一行必须换成 Context 变量标签" code={systemPrompt} />

  在 User（用户消息）编辑区输入“本次问题：”，然后通过选择器插入“User Input → question”。
  如果编辑器已预填旧提示词，先在本应用草稿中替换旧内容，避免两套要求同时存在。

  <MockWindow title="根据资料回答：变量位置教学仿真">
    <div className="mock-form-grid">
      <MockField label="Context 字段">查活动资料 → result</MockField>
      <MockField label="System 最末尾">可用资料：［Context 变量标签］</MockField>
      <MockField label="User 消息">本次问题：［User Input → question 变量标签］</MockField>
      <MockField label="生成结果">text：模型输出的文字</MockField>
    </div>
  </MockWindow>

  <strong>成功状态：</strong>模型同时收到本次问题与本次检索资料，不需要凭空补全活动规则。
  <strong>失败判断：</strong>变量标签缺失、仍残留方括号占位提示，或引用了上次手工测试的固定内容；先修改绑定。
  提示词只能引导生成，不能保证消除幻觉（生成看似可信、实则缺乏依据的内容），也不能当作秘密保险箱。
</section>

<section className="book-section" id="book06-07-sources">
  ## 第五步：把实际检索片段单独输出

  来源不能让模型自己编。我们用模板直接整理检索结果，并把它与模型答案放在两个字段中。
  这份来源清单列的是本次候选材料，不宣称每一段都支持回答。

  在 LLM 后添加 Template 节点，命名为“列出候选来源”。在输入变量列表新增名称 `chunks`，
  值选择“查活动资料 → result”。chunks 是本模板给片段数组起的本地名称。随后粘贴以下模板。

  <CodeBlock label="粘贴到“列出候选来源”的模板编辑区" code={referenceTemplate} />

  模板使用 Jinja2 语法：`for` 表示逐项处理，`loop.index` 自动编号，`title` 取标题，`content`
  取原文片段，`default` 在字段缺失时给出提示。你不需要编写程序；保持符号不变，只核对 chunks 的绑定。
  这里没有让模型生成网址，也不输出资料的内部标识或秘密链接。
  [官方模板节点说明](https://docs.dify.ai/en/self-host/use-dify/nodes/template)

  把原来 LLM 直达旧 Output 的连线移除，再把“列出候选来源”接到这个 Output，改名“返回回答与来源”。
  清除旧的输出字段，新增下面两项；每个值都从选择器选择，不手工输入变量名称。

  <ComparisonTable>

  | 输出名称 | 选择的值 | 阅读时的意义 |
  | --- | --- | --- |
  | `answer` | 根据资料回答 → text | 模型生成的答案，需要人工核对 |
  | `references` | 列出候选来源 → output | 本次检索实际返回的候选标题和片段 |

  </ComparisonTable>

  空结果分支的 notice 和有结果分支的 answer、references 名称互不重复。Output 只声明工作流要
  返回的数据；多个 Output 不会自动停止其他并行分支，所以仍须确认本章两条线互斥。
  [官方输出节点说明](https://docs.dify.ai/en/self-host/use-dify/nodes/output)

  <strong>成功状态：</strong>有结果这条线是 LLM → 来源模板 → Output，输出能追溯到实际节点。
  <strong>失败判断：</strong>只见答案、来源显示变量名原文、模板报错或仍有旧旁路；先修正连线和字段再试跑。
</section>

<section className="book-section" id="book06-07-test">
  ## 第六步：分别检查“有依据”“无候选”“有候选但不能回答”

  运行会把问题与片段发给远程模型，可能收费。先核对剩余次数与用量，再在画布点击 Test Run（测试运行），
  每次只输入一个问题。请求后等运行结束并查看账单；未完成或用量不明时不再点第二次。

  <ComparisonTable>

  | 检查场景 | 先看哪份证据 | 通过标准 / 失败处理 |
  | --- | --- | --- |
  | 问“报名什么时候截止” | 检索输出与合成资料原文 | 命中截止段，answer 不改变“活动前 2 天”，references 包含原文；不符先查分段与绑定 |
  | 问资料未提的“交通补贴多少” | 先看 result 是否为空 | 空则只返回 notice，LLM 未执行；非空则检查片段能否支持，不能把它误记成空分支测试 |
  | 有候选但没有所问规则 | 候选片段与 answer 对照 | 应回答资料不足；编造补贴数额就判失败，不因来源栏有文字而通过 |

  </ComparisonTable>

  “问一个无关问题”不保证检索一定返回空数组。要单独核验条件，可选中“有资料吗”，在节点测试面板
  将 result 测试输入设为数组 `[]`，再点该节点的 Run（运行），确认走 IF；随后用含一项的数组检查 ELSE。
  如果当前界面需要从 Variable Inspector（变量检查器）编辑缓存值，就在该处修改 result，再单独运行条件节点。
  只测试条件节点，不测试 LLM；测试后清除或恢复测试值，再做一次完整流程核对。
  [官方单节点调试说明](https://docs.dify.ai/en/self-host/use-dify/debug/step-run)

  这只能证明注入空值时条件判断正确，不能证明真实检索的空结果链路已通过。后续实机记录要分别保存
  “条件注入测试”和“真实未命中整次运行”；如果真实检索始终返回候选，就把后者记为未覆盖，不编造成功记录。

  打开本次运行的执行详情，依次看输入、检索 result、选中分支、执行节点与最终输出。空结果整次运行中
  LLM 应显示未执行，不能有模型请求或 token 用量；有结果时也要与提供方记录核对，不能只看页面上一句
  “本次没有调用生成模型”。那句话是固定文本，本身不是计费证据。
</section>

<section className="book-section" id="book06-07-handoff">
  ## 完成后：保存草稿与问题清单

  - 能顺着每条连线说明问题和资料从哪里来，确认没有直达模型的旁路。
  - 真实空结果走固定分支；若尚未取得真实空样本，明确记为未覆盖。
  - 有候选时答案与来源分开显示，能指出支持答案的具体文字。
  - 依据不足仍可能生成错误答案，已逐题核对而不是承诺“零幻觉”。
  - 保存草稿，记录通过、失败和未覆盖场景，以及请求次数与用量；不导出真实日志到公共仓库。

  下一章已提供 E01—E06 六类检查，涵盖中文改写、输入边界、恶意要求和资料停用/恢复，再讨论导出与版本。
  本章不提前发布应用，不创建外部调用凭证。关闭浏览器不保证后台运行已取消；异常请求应按提供方
  支持的停止或撤销方式处理，并核对最终用量。
</section>
