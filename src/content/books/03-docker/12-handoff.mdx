<section className="book-section" id="ch12-result">
  ## 这一章要解决什么

  一套服务“今天能打开”，不等于“下个月还能维护”。当你忘记项目目录、端口、镜像版本、数据位置和备份方法时，即使容器仍在运行，也很容易因为一次更新或清理失去控制。

  本章不再增加新的 Docker 功能，而是把前面章节已经完成的结果整理成可交接状态：

  <FlowDiagram>
    <div className="flow-node">
      <strong>声明</strong>
      <small>compose.yaml 能解析</small>
    </div>
    <div className="flow-node">
      <strong>运行</strong>
      <small>service、镜像、端口和策略</small>
    </div>
    <div className="flow-node">
      <strong>数据</strong>
      <small>bind mount 与备份位置</small>
    </div>
    <div className="flow-node">
      <strong>验证</strong>
      <small>状态、curl 和日志证据</small>
    </div>
    <div className="flow-node">
      <strong>边界</strong>
      <small>没有公网入口与敏感值</small>
    </div>
    <div className="flow-node">
      <strong>下一步</strong>
      <small>域名或新的 Compose 应用</small>
    </div>
  </FlowDiagram>

  最终交付物是一份 `HANDOFF.md`。它记录“去哪里查”和“怎样验证”，但绝不记录密码、SSH 私钥、API token、第二册 UUID、Reality 私钥或订阅 URL。
</section>

  <ComparisonTable>

  | 文件或目录 | 是否应该交接 | 交接内容 |
  | --- | --- | --- |
  | `compose.yaml` | 是 | 完整文件和校验方法 |

  | Docker 数据目录 | 否 | 不手工移动 daemon 内部文件 |
  | 本机备份 | 是 | 文件名、日期、异机副本状态 |

  </ComparisonTable>

  保存后，把权限限制为只有当前账户可以读写，并做一次敏感信息模式检查：

  <CodeBlock label="限制权限并检查交接卡" code={verifyHandoff} />

  成功状态：

  - 第一条 grep 能列出五类必要信息；
  - 后两条敏感模式检查没有输出；
  - 模板中的 `<YYYY-MM-DD>`、负责人和镜像占位项已经替换；
  - 文件没有真实登录凭证、IP 地址、私钥、token 或订阅信息。

  失败判断：

  - 后两条检查有输出：人工检查命中行；如果是真实公网 IP 或凭证，立即从文档删除，凭证还要按泄漏处理流程轮换；
  - 仍有尖括号占位项：交接尚未完成；
  - 记录的路径或端口与 inspect 不一致：以验证过的运行状态为依据修正文档；
  - 备份只记录“已备份”而没有文件位置和日期：未来维护者无法验证。

  <Callout type="warning" title="正则检查只是辅助">
    grep 无输出不能证明文件绝对没有秘密。它只能发现几种常见模式，最终仍需人工逐行阅读；提交到 Git 前还要再次检查 diff。
  </Callout>
</section>
