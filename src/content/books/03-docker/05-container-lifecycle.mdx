<section className="book-section" id="ch5-result">
  ## 为什么需要另一个容器

  `hello-world` 的主进程打印完文字就结束，适合验证安装，却不适合观察持续运行状态。

  本章使用 `nginx:1.30.4-alpine` 创建一个不发布端口的练习容器：

  - Nginx 主进程会持续运行；
  - 不使用 `-p`，所以不会把 Web 端口发布到主机；
  - 不挂载目录或 volume；
  - 不写入真实业务数据；
  - 名称固定为 `book03-lifecycle`；
  - 完成后只删除这个练习容器，保留镜像供后续章节使用。

  <Callout type="warning" title="镜像里有 Web 服务，不等于已经开放公网">
    本章没有端口发布参数。容器可以在自己的网络空间监听 80，但主机和公网没有因此获得对应入口；端口关系下一章再讲。
  </Callout>
</section>

<section className="book-section" id="ch5-model">
  ## 容器状态怎样变化

  <FlowDiagram>
    <div className="flow-node">
      <strong>Created</strong>
      <small>对象已创建，主进程未运行</small>
    </div>
    <div className="flow-node">
      <strong>Running</strong>
      <small>主进程正在运行</small>
    </div>
    <div className="flow-node">
      <strong>Exited</strong>
      <small>主进程已经结束</small>
    </div>
    <div className="flow-node">
      <strong>Removed</strong>
      <small>容器对象已删除</small>
    </div>
  </FlowDiagram>

  `Removed` 不是 Docker 列表中的运行状态，因为对象已经不存在。它是本章用于表达“生命周期结束”的教学节点。

  <ComparisonTable>

  | 操作 | 容器是否存在 | 主进程是否运行 | 镜像是否存在 |
  | --- | --- | --- | --- |
  | create 后未启动 | 是 | 否 | 是 |
  | start / run 后 | 是 | 是，除非程序立即退出 | 是 |
  | stop 后 | 是 | 否 | 是 |
  | rm 后 | 否 | 否 | 通常仍是 |

  </ComparisonTable>
</section>

  ## 第一步：在后台运行持续服务

  <InstructionStep number={1} title="创建具名 Nginx 容器">
    `-d` 是 detached mode（分离模式），让容器在后台运行，终端立即返回容器 ID。

  <CodeBlock
    label="创建 book03-lifecycle"
    code={lifecycleRun}
  />

  命令拆解：

  <ComparisonTable>

  | 片段 | 作用 |
  | --- | --- |
  | `run` | 从镜像创建并启动新容器 |
  | `-d` | 在后台运行，输出容器 ID |
  | `--name book03-lifecycle` | 赋予固定容器名称 |
  | `nginx:1.30.4-alpine` | 使用明确版本的 Nginx Alpine 镜像 |

  第一次使用该镜像时会先拉取多个 layer。完成后，终端输出一串完整容器 ID。

  - 拉取超时：检查 DNS 和 Docker Hub 连接；
  - 架构错误：核对 amd64 支持；
  - daemon 错误：返回第 3 章；
  - 磁盘不足：停止，不执行清理命令碰运气。

<section className="book-section" id="ch5-running">
  ## 第二步：确认 Running

  <CodeBlock
    label="查看运行中的 book03-lifecycle"
    code={'sudo docker ps --filter "name=book03-lifecycle"'}
  />

  重点列：

  <TerminalMock title="运行中容器示意">
    CONTAINER ID&nbsp;&nbsp; IMAGE&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; STATUS&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; PORTS&nbsp;&nbsp; NAMES<br />
    a1b2c3d4e5f6&nbsp;&nbsp; nginx:1.30.4-alpine&nbsp; Up ...&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; 80/tcp&nbsp; book03-lifecycle
  </TerminalMock>

  `Up ...` 表示容器主进程仍在运行。

  `80/tcp` 只说明镜像或容器声明了容器内端口，不表示主机已经发布端口。真正发布后，PORTS 列会出现主机地址和箭头关系。

  <Callout type="info" title="容器 ID 与运行时间每次都不同">
    不要把仿真 ID 复制进命令。本书始终使用 `book03-lifecycle` 名称操作。
  </Callout>
</section>

<section className="book-section" id="ch5-inspect-running">
  ## 第三步：读取当前状态和重启策略

  <CodeBlock
    label="检查状态、Running 布尔值与重启策略"
    code={lifecycleInspect}
  />

  初始预期：

  ```text
  状态=running 运行中=true 重启策略=no
  ```

  布尔值只有 `true` 和 `false`，用来表示“是”与“否”。

  `重启策略=no` 表示本章创建时没有要求 Docker 在容器退出或 daemon 重启后自动恢复它。`no` 是 restart policy 的默认值，不代表容器无法手动 `restart`。
</section>

<section className="book-section" id="ch5-stop">
  ## 第四步：停止但不删除

  <InstructionStep number={1} title="向容器主进程发送正常停止请求">
    `docker stop` 会先给容器主进程机会正常退出；如果它没有在停止期限内结束，Docker 才会继续强制终止。
  </InstructionStep>

  <CodeBlock
    label="停止 book03-lifecycle"
    code="sudo docker stop book03-lifecycle"
  />

  成功输出：

  ```text
  book03-lifecycle
  ```

  现在分别查看两个列表：

  <CodeBlock
    label="比较 ps 与 ps -a"
    code={'sudo docker ps --filter "name=book03-lifecycle"\nsudo docker ps -a --filter "name=book03-lifecycle"'}
  />

  第一条通常没有输出，因为它只看运行中容器；第二条仍能看到 `book03-lifecycle`，状态变为 Exited。

  <Callout type="info" title="stop 不会删除容器配置">
    容器名称、使用的镜像、网络配置和可写层仍然存在。下一步可以启动同一个容器，而不是重新 run 一个新容器。
  </Callout>
</section>

<section className="book-section" id="ch5-start">
  ## 第五步：启动原来的容器

  <CodeBlock
    label="启动已存在的 book03-lifecycle"
    code="sudo docker start book03-lifecycle"
  />

  成功后再次执行：

  <CodeBlock
    label="确认恢复为 Running"
    code={lifecycleStatus}
  />

  状态应重新变为 `Up ...`。

  这一步没有创建新容器：

  - 名称仍是 `book03-lifecycle`；
  - 容器 ID 仍与停止前相同；
  - 使用相同镜像和配置；
  - 可写层仍属于原容器。

  如果使用 `docker run`，则会创建另一个容器；相同名称还会触发冲突。
</section>

<section className="book-section" id="ch5-restart">
  ## 第六步：执行一次受控 restart

  `restart` 把“停止原容器”和“重新启动原容器”组合在一起：

  <CodeBlock
    label="重启 book03-lifecycle"
    code="sudo docker restart book03-lifecycle"
  />

  成功输出仍是容器名称。随后：

  <CodeBlock
    label="确认 restart 后状态"
    code={lifecycleInspect}
  />

  应看到：

  ```text
  状态=running 运行中=true 重启策略=no
  ```

  <Callout type="warning" title="restart 不是万能排错按钮">
    如果应用配置错误、端口冲突或数据损坏，反复 restart 不会修复原因。第 10 章会先看状态和日志，再决定是否重启。
  </Callout>
</section>

<section className="book-section" id="ch5-policy">
  ## 手动 restart 与 restart policy 不同

  restart policy 是容器创建配置的一部分，用来规定容器退出或 Docker daemon 重启时是否自动尝试恢复。

  <ComparisonTable>

  | 策略 | 基本含义 | 使用边界 |
  | --- | --- | --- |
  | `no` | 不自动重启，默认值 | 练习与一次性任务常见 |
  | `on-failure` | 主进程以非零状态退出时重启 | 可选最大重试次数 |
  | `always` | 容器停止后持续尝试恢复 | 手动停止与 daemon 重启行为需理解 |
  | `unless-stopped` | 类似 always，但保留明确的手动停止意图 | 本书 Compose 样章使用 |

  </ComparisonTable>

  自动重启适合恢复意外退出，不适合掩盖持续崩溃。如果容器不断 Restarting，应查看日志和配置，而不是不断扩大重试。

  本章不修改 `book03-lifecycle` 的策略；第 9 章会在可阅读的 Compose 文件中设置 `unless-stopped`。
</section>

<section className="book-section" id="ch5-remove-running">
  ## 第七步：先观察“运行中不能普通删除”

  容器当前正在运行。不要实际输入强制删除命令，只记住：

  - 普通 `docker rm book03-lifecycle` 会拒绝删除运行中容器；
  - `docker rm -f` 会强制处理运行对象，扩大误操作风险；
  - 本书主线先 `stop`、再核对、最后定向 `rm`。

  <Callout type="danger" title="本章不提供 rm -f 的复制按钮">
    遇到删除失败时先看状态，而不是把 `-f` 当作通用修复。强制删除真实业务容器可能造成请求中断和未完成写入。
  </Callout>
</section>

    label="删除前确认对象"

  <InstructionStep number={3} title="删除这个已停止的容器">
    `rm` 只作用于明确名称，不删除镜像。

  <CodeBlock
    label="删除 book03-lifecycle"

  />

  成功输出 `book03-lifecycle`。

    label="确认容器对象已经不存在"

<section className="book-section" id="ch5-clean-hello">
  ## 第九步：清理上一章的 hello-world 容器

  `book03-hello` 是第 4 章明确创建、没有业务数据且状态为 Exited 的练习对象。先核对：

  <CodeBlock
    label="核对 book03-hello"
    code={'sudo docker ps -a --filter "name=book03-hello"'}
  />

  只有同时看到：

  - `IMAGE` 为 `hello-world:latest`；
  - `STATUS` 为 Exited；
  - `NAMES` 为 `book03-hello`；

  <CodeBlock

  />

<section className="book-section" id="ch5-danger">
  ## 批量清理命令为什么暂不出现

  <ComparisonTable>

  | 命令类型 | 可能影响 | 当前做法 |
  | --- | --- | --- |
  | container prune | 所有满足条件的已停止容器 | 只按明确名称删除练习对象 |
  | image prune | 未使用镜像或缓存 | 保留后续需要的镜像 |
  | volume prune | 未被容器引用的 volume | 第 7、11 章在数据边界下处理 |
  | system prune | 跨多类 Docker 对象 | 不作为日常排错命令 |

  </ComparisonTable>

  “当前没在运行”不等于“以后不需要”。批量命令必须在备份、对象清单和影响范围都明确后使用。
</section>

<section className="book-section" id="ch5-failures">
  ## 常见失败与判断

  <ComparisonTable>

  | 现象 | 先检查 | 不要立刻做什么 |
  | --- | --- | --- |
  | `docker ps` 看不到容器 | 是否已经停止，改用 `ps -a` | 不要重新 run 同名容器 |
  | `start` 后立即 Exited | 主进程和日志 | 不要不断 restart |
  | 删除提示容器运行中 | 当前状态和名称 | 不要加 `-f` |
  | `No such container` | 名称、是否已经删除 | 不要猜随机 ID |
  | Nginx 镜像拉取失败 | DNS、Hub、磁盘、架构 | 不要换未知 registry |
  | PORTS 只有 `80/tcp` | 尚未发布主机端口 | 不要改云防火墙 |
  | 删除容器后镜像仍在 | 这是预期对象边界 | 不要误判删除失败 |

  </ComparisonTable>
</section>
