# Claude：长文、分析与审阅协作

长文任务最怕目标含糊。先说明读者、篇幅、语气和不能改变的事实，再让 AI 按章节或段落工作。不要一次要求“全面优化”，那会让你无法定位变化。

## 对话、Project 和 Claude Code 不是同一件事

普通对话适合处理当前上传的资料。Claude Projects 可以集中项目知识和项目指令，让同一项目中的多次对话共享经过放入项目知识的背景。Claude Code 则是面向项目目录和工具的工作方式，会涉及文件与执行权限。

本章使用长文审阅作为练习，不要求安装 Claude Code。不同套餐是否提供 Projects、共享和其他能力，应以当前官方页面为准。

## 准备长文审阅包

不要只上传正文。一起准备：

- 目标读者说明；
- 必须保留的事实与专有名词；
- 希望检查的三项问题；
- 不允许改写的段落；
- 输出格式。

例如，本轮只检查“新手是否看得懂”“步骤是否跳跃”“成功状态是否明确”，暂时不改写作者风格。

可以要求它输出“原文位置—问题—理由—建议”，并把不确定的判断单独列出。你保留最终决定，尤其是事实、引用、法律和对外承诺。

```text
请先审阅，不要重写全文。按“原文位置、问题、理由、建议”输出。
如果判断依赖我没有提供的事实，请标记“待确认”。
不要改变引用、数字和承诺性表述。
```

## 分段修改

先选择一段验证标准是否合适。确认后再继续下一节。若整篇一次改写，你会很难判断哪些变化解决了问题，哪些只是改变了风格。

Claude 官方帮助中心说明，Projects 可以保存项目知识和项目指令；对话内容是否在其他对话中可用，取决于是否进入项目知识等当前机制。不要假设“同一个项目里的所有聊天都会自动互相记得”。

## 本章验收

成功状态是每条意见都能回到原文位置，修改范围经过你确认。失败判断是只有漂亮的改写，却没有证据和取舍理由，或者项目知识混入了不应共享的资料。
