# 建立自己的提示与模板库

模板不是一段神奇咒语，而是把稳定的工作方法写下来。至少保存任务简报、文件清单和交付检查表三类模板。

好的模板保留任务结构，把会变化的内容留成空格。它能提醒你补齐目标、资料和验收标准，也允许你删掉不适用的部分。

## 建立一个普通文件夹就够了

在自己的文档目录中新建 `AI-工作模板` 文件夹，先放四个文本文件：

```text
AI-工作模板/
├── 01-任务简报.md
├── 02-资料清单.md
├── 03-结果审阅.md
└── 04-交付记录.md
```

这一步的目的不是搭建复杂知识库，而是让模板可查找、可复制、可修改。成功状态是你关闭 AI 工具后仍能找到这些文件。失败判断是模板只保存在某一次聊天里，之后无法复用。

## 任务简报模板

```text
任务名称：
目标：
使用者或读者：
允许使用的资料：
不得使用的资料：
输出文件与格式：
修改范围：
验收标准：
必须暂停并询问我的情况：
```

“必须暂停”的一栏适合写付款、删除、公开发布和向外发送等动作。如果当前工具无法在执行前暂停，就不要授予它相应权限。

## 资料清单模板

```text
资料名称：
位置：
用途：
日期或版本：
是否包含敏感内容：
是否允许进入第三方工具：
```

同一资料可能在不同任务中有不同权限。例如，公开产品手册可以用于摘要，内部客户名单通常不能放进个人 AI 账户。

## 结果审阅模板

```text
[ ] 对象和读者正确
[ ] 关键事实能找到来源
[ ] 推断和未知项已标记
[ ] 输出格式符合要求
[ ] 未修改无关文件
[ ] 未发生未经确认的发送、发布、付款或删除
```

## 模板也需要版本

在文件末尾记录日期和一次简短变化：

```text
2026-09-12：新增“必须暂停”的条件，避免在发送前遗漏人工确认。
```

每次复用前更新读者、资料、日期和限制；每次完成后记录哪些地方仍需要人工补充。如果模板连续三次出现同一种遗漏，就把相应检查项写进去。

不要把密码、API Key、真实客户资料或不可公开的内部规则写进通用模板。模板可以写“从已批准的密码管理器获取凭证”，但不应保存凭证本身。

## 不要把模板变成僵硬流程

模板过长时，人会跳过所有内容。保留真正影响结果和风险的字段，把产品按钮名称、临时网址和一次性要求放进具体任务，而不是塞进通用模板。

## 本章验收

成功状态是四个模板能被你或同事读懂并修改，下一次任务不需要从空白提示开始。失败判断是模板越来越长，却没有让验收更清楚，或者模板本身变成敏感信息仓库。
