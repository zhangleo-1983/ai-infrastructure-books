## 先画出一条没有外部写入的路径

手动触发节点只负责开始运行。接下来的 Set（字段设置）节点把一段输入拆成姓名、日期和人数，最后由 Edit Fields 或 Code 以外的内置字段节点生成摘要。教学仿真如下：

<MockWindow title="报名整理器：教学仿真">
  <ol>
    <li><strong>Manual Trigger：</strong>你点击 Execute workflow 后开始。</li>
    <li><strong>Set：</strong>写入 `raw_text`、`event_date` 和 `guest_count`。</li>
    <li><strong>IF：</strong>判断 `guest_count` 是否小于等于 2。</li>
    <li><strong>Set：</strong>分别输出“可以登记”或“需要人工确认”。</li>
  </ol>
</MockWindow>

## 第一步：建立输入和预期结果

在自己的电脑打开受保护的 n8n 管理界面，创建一个空工作流，命名为“活动报名整理器（练习）”。先保存名称，再添加 Manual Trigger。节点出现且没有红色错误时，点击 Execute workflow；此时运行应该立即结束，因为还没有后续节点。

接着添加字段节点，写入下面的低敏感样本。字段名必须使用英文下划线，避免后续表达式引用错对象。

<CodeBlock label="字段值：仅用于练习" code={`raw_text=林林，周六下午，带一位朋友\nevent_date=周六下午\nguest_count=2`} />

把字段节点连到输出节点，再执行一次。成功状态是执行记录中能看到三项输入和一份摘要；失败判断是节点未执行、字段名拼错，或输出里出现没有输入来源的内容。先打开失败节点查看输入和错误，再改一个地方后重跑，不要连续点击制造一串难以区分的记录。

## 第二步：读执行记录而不是只看绿色图标

每次运行都有独立的执行记录。打开记录，依次核对触发时间、每个节点的输入、输出和耗时。若某节点显示成功但输出为空，向上查看它收到的字段；若表达式显示 `undefined`，说明字段名或连线不匹配。

<strong>成功状态：</strong>你可以从记录复述“输入是什么、哪一步改了它、最终输出是什么”。<strong>失败判断：</strong>只能凭画布颜色判断成功，或把一次失败重跑后的最新记录当成第一次结果；此时保留失败记录并回到对应节点。

## 第三步：把输入变成可检查的字段

在字段节点中保留 `raw_text`，另加 `event_date` 和 `guest_count`。字段值来自练习输入，不来自凭证或外部请求。运行后打开 JSON 视图，确认数字字段确实是数字；如果它被保存成字符串，后面的条件比较可能得到意外结果。

不要一开始加入 Code 节点。内置字段节点更容易在执行记录中解释，也不需要授予在主机上运行代码的能力。等你能逐项说明输入和输出，再评估是否真的需要脚本。

<strong>成功状态：</strong>一次执行中每个字段都有明确来源和类型。<strong>失败判断：</strong>为了修复类型问题直接加入任意 JavaScript，或把整段原始文本交给外部系统；先停下来记录差异。
