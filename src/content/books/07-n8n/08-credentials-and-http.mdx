## 凭证保存什么

凭证是 n8n 加密保存的授权配置，可能包含 API key、OAuth 刷新令牌或用户名密码。工作流 JSON 通常只引用凭证名称；备份时必须同时考虑加密密钥和凭证存储。把 key 直接写进 URL、表达式或 Set 节点，会扩大泄露范围。

| 项目 | 应该放在哪里 | 检查方法 |
| --- | --- | --- |
| API key | n8n 凭证 | 只显示脱敏状态，不复制到聊天 |
| 请求 URL | HTTP Request 节点 | 核对主机名和方法 |
| 非秘密参数 | 节点字段 | 在执行记录中确认是否可公开 |
| 响应数据 | 执行记录 | 设定保留时间并清理样本 |

## 用无副作用请求练习

先创建没有凭证的 HTTP Request 节点，选择明确的 GET 方法和练习 URL。运行后查看状态码、响应头和正文，再决定是否需要映射字段。请求失败时先判断是 DNS、TLS、认证、限流还是业务状态，不要通过关闭证书验证或无限重试“修好”它。

<strong>成功状态：</strong>能指出请求的目的地、方法、是否携带凭证和响应保存位置。<strong>失败判断：</strong>在不清楚权限范围时导入社区凭证节点，或把真实 key 写入 Code 节点；立即删除临时凭证并停止。
