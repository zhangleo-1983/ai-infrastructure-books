  ## 先检查 443 端口是否空闲

  <CodeBlock code={"ss -lntp | grep ':443 '"} />

  没有任何输出通常表示 443 未被监听，可以使用；有输出则说明已有服务占用。新手可以改用 `8443`，或者先查清占用者。

  <Callout type="info" title="为什么优先 443？">
    443 是标准 HTTPS 端口，通常网络兼容性最好。但“使用 443”不是成功的必要条件，端口冲突时不要强行抢占。
  </Callout>

  ### 基础字段怎么选

  <ComparisonTable>

  | 字段 | 建议值 | 解释 |
  | --- | --- | --- |
  | Remark | `My-Reality` | 仅用于你自己识别节点 |
  | Protocol | `VLESS` | 轻量、使用 UUID 验证，不依赖 VMess 的时间机制 |
  | Port | `443` 或未占用端口 | 客户端必须使用同一端口 |
  | Transmission | `TCP / RAW` | 与 Reality + Vision 的入门组合直接、稳定 |
  | Security | `Reality` | 启用 Reality 握手与相关密钥字段 |

  </ComparisonTable>

  <Callout type="info" title="UUID 可以理解成客户端通行证">
    别人获得 UUID 和完整连接参数后，可能使用你的节点。每台自己的设备建议创建独立客户端，而不是多人共享同一 UUID。
  </Callout>

  <Callout type="tip" title="Flow 选择 xtls-rprx-vision">
    本书使用 VLESS + TCP/RAW + Reality + Vision 的组合。不要把 Flow 留空后再照搬 Vision 参数；协议字段必须前后一致。
  </Callout>

<section className="book-section" id="ch5-save">
  ## 保存、放行端口并检查监听

  <InstructionStep number={1} title="保存入站">
    确认状态为启用，客户端数量至少为 1。
  </InstructionStep>

  <InstructionStep number={2} title="若 UFW 已启用，放行节点端口" />

  <CodeBlock label="使用 443 时" code="ufw allow 443/tcp" />

  <InstructionStep number={3} title="检查 Xray 是否监听端口" />

  <CodeBlock code={"ss -lntp | grep ':443 '"} />

  应当看到 Xray 或相关进程监听 `0.0.0.0:443`、`[::]:443` 或服务器对应地址。

  <Callout type="warning" title="使用 Vultr Firewall 时也要放行">
    系统内 UFW 放行不代表云防火墙自动放行。若实例绑定了 Vultr Firewall Group，还要在控制台增加相同 TCP 端口规则。
  </Callout>
