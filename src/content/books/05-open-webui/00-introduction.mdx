<section className="book-section" id="book05-start-not-model">
  ## 先纠正一个最重要的误解

  **Open WebUI 是 AI 对话与管理界面，不是大语言模型。**

  本书主线不会让普通 CPU VPS 在本机运行巨大模型。VPS 负责显示界面、验证用户、保存应用数据，
  然后通过 HTTPS 把经过授权的请求发送给远程模型接口。

  <ComparisonTable>

  | 对象 | 本书中负责什么 | 不负责什么 |
  | --- | --- | --- |
  | Open WebUI | 登录、聊天界面、模型选择、历史记录和管理员设置 | 不凭空生成模型回答，也不替读者支付模型费用 |
  | 模型 | 根据输入生成回答 | 不管理你的域名、Tunnel 或 Open WebUI 用户 |
  | API | 让两个程序按约定格式交换请求和响应 | 不是一个账户，也不是一笔固定价格 |
  | API endpoint | 接收模型请求的网络地址，例如提供方的 `/v1` 接口 | 不是 Open WebUI 的公开聊天网址 |
  | API key | 让模型提供方识别调用者和权限的秘密凭证 | 不是登录 Open WebUI 的密码 |

  </ComparisonTable>

  如果提供方采用 OpenAI 常见的 Chat Completions 请求格式，Open WebUI 会把它称为
  **OpenAI-compatible API**，也就是“OpenAI 兼容接口”。名称中的 OpenAI 描述的是接口格式，
  不代表服务一定由 OpenAI 公司提供。
</section>

<section className="book-section" id="book05-start-two-paths">
  ## 一次聊天同时经过两条路径

  <OpenWebUIPathMap labelId="book05-start-path-title" />

  两条路径必须分别验收：

  - 路径 A 失败：用户连登录页都打不开，应先查 DNS、HTTPS、Tunnel、connector 或本机应用；
  - 路径 A 成功、路径 B 失败：页面可以登录，但模型没有回答，应查连接配置、API key、模型 ID、额度或模型提供方；
  - 两条路径都成功：还要核对用量、数据保存位置、注册策略与备份，不能只看一次回答。

  <Callout type="warning" title="“页面能开”不等于“模型能用”">
    Cloudflare 不替 Open WebUI 提供模型；Open WebUI 也不能替模型提供方恢复额度。后续排错会始终先问：失败发生在路径 A，还是路径 B？
  </Callout>
</section>

<section className="book-section" id="book05-start-missing-handoff">
  ## 如果旧 VPS 或 Tunnel 已经清理

  “完成过前一册”不等于那些临时资源必须永远运行。你可能已经为了停止计费销毁 VPS，也可能只保留
  域名、Cloudflare zone 与 DNSSEC。此时不要把旧地址、旧 token 或已经删除的 connector 填进第五册。

  <ComparisonTable>

  | 当前情况 | 现在做什么 | 不要做什么 |
  | --- | --- | --- |
  | 原 VPS 与 Tunnel 都在，且明确没有未知业务 | 先做只读资源与 route 清点，再决定是否复用 | 不因为“看起来空闲”就停止 connector 或覆盖 route |
  | VPS 在，Tunnel 已删除 | 先确认 VPS 资源和费用，再按第四册方法建立一个归属明确的 Tunnel | 不复用失效 token，也不同时安装多个 system service |
  | VPS 已销毁，只保留域名与 zone | 回第一册建立隔离 VPS，再回第三册安装 Docker、回第四册建立 Tunnel | 不把历史 IP、主机指纹或已删除实例当作当前值 |
  | 对象归属或持续费用说不清 | 停止，先找到账户负责人、账单与资产清单 | 不新建第二套资源来掩盖未知对象 |

  </ComparisonTable>

  新建 VPS 会开始持续计费；创建 Tunnel 会改变外部账户状态。两者都必须放进实机 runbook 的明确闸门，
  不能因为这一节说明了恢复路径就自动执行。
</section>

<section className="book-section" id="book05-start-port">
  ## 第三步：确认主机 3000 端口没有冲突

  本书计划让 Open WebUI 的主机端只监听 `127.0.0.1:3000`，容器内部仍使用 8080。先执行：

  <CodeBlock
    label="查看主机 3000 端口"
    code={portBaseline}
  />

  `ss` 是查看网络 socket（套接字）状态的工具。这里没有输出通常表示端口尚未被进程监听，
  可以进入后续规划；如果出现输出，则记录进程和监听地址：

  - `127.0.0.1:3000`：已有本机服务占用；
  - `0.0.0.0:3000`：已有服务在所有 IPv4 网卡监听；
  - `[::]:3000`：已有服务可能在所有 IPv6 网卡监听；
  - 陌生进程：不要停止它，先找到负责人和用途。

  成功状态不是“3000 必须为空”，而是你能解释占用情况。第 3 章可以选择另一个未冲突的回环端口，
  但公开 route、文档和交接卡必须保持一致。
</section>

  `base URL` 是接口的基础地址，`model ID` 是提供方用来精确识别模型的字符串。两者都不是秘密，
  但真实账户页面、余额和资源 ID 仍不应出现在公开截图中。

  API key 必须满足：

  - 为这次 Open WebUI 连接单独创建；
  - 只具有普通模型调用需要的权限；
  - 可以单独撤销，不依赖删除整个账户；
  - 具有合理的额度、预算或告警；
  - 保存在密码管理器，不写入这张卡；
  - 不是提供方的账户管理主密钥。

  如果提供方不允许限制权限，也无法设置余额或支出保护，先判断自己是否接受风险，不要因为已经注册就继续。
</section>

<section className="book-section" id="book05-start-costs">
  ## 第六步：把四种费用分开记录

  <ComparisonTable>

  | 费用 | 常见计费方式 | 停止后是否自动消失 | 本书要求 |
  | --- | --- | --- | --- |
  | VPS | 按小时或按月 | 停止实例不一定停止计费 | 确认销毁方法与附加资源 |
  | 域名 | 按年续费 | 关闭网站不取消续费 | 记录到期日、自动续费和负责人 |
  | Cloudflare | 本书主线可使用 Free 能力 | 仍需核对账户中是否有其他付费产品 | 不把付费功能作为完成前提 |
  | 模型 API | 按 token、请求、额度或套餐 | 关闭 Open WebUI 不一定取消余额或订阅 | 设置限额，测试后核对实际用量 |

  </ComparisonTable>

  token（词元）是模型处理文字时使用的计量单位，不等同于一个汉字或一个单词。输入、历史上下文和输出都可能计入用量。

  <Callout type="warning" title="一次点击可能不只产生一次模型请求">
    Open WebUI 的标题、标签、搜索查询等后台功能可能额外调用模型。第一次测试必须同时查看 Open WebUI 结果与提供方用量，而不是假设“发一条消息就只计费一次”。
  </Callout>
</section>

<section className="book-section" id="book05-start-data-boundary">
  ## 第七步：先决定什么数据不能进入练习

  “自托管 Open WebUI”只说明界面与应用数据由你的服务器管理，不等于所有内容都停留在 VPS。

  <ComparisonTable>

  | 数据 | 可能保存在 VPS | 可能发送给模型提供方 | 本轮练习边界 |
  | --- | --- | --- | --- |
  | 账户资料 | 是 | 通常不需要 | 使用专用教学账户，不显示真实邮箱 |
  | 聊天文字 | 是 | 是，生成回答所必需 | 只使用无隐私的测试问题 |
  | 历史上下文 | 是 | 可能随下一次请求再次发送 | 不粘贴工作秘密或个人敏感信息 |
  | 附件 | 是 | 取决于处理与模型功能 | 样章阶段不上传文件 |
  | 模型 API key | 由管理员连接保存 | 用于向提供方鉴权 | 不进截图、日志摘录或仓库 |
  | Tunnel token | 由 connector 使用 | 不应发送给模型 | 不放进 Open WebUI Compose |

  </ComparisonTable>

  本书不提供法律结论。处理组织数据、客户数据、健康信息、身份证件或其他受监管内容前，
  必须获得相应授权并阅读模型提供方当前的数据处理政策。
</section>

      <div className="mock-panel">
        <strong>数据边界</strong>{" "}
        <MockStatusBadge tone="neutral">只使用无隐私测试文字，不上传文件</MockStatusBadge>
      </div>
    </div>
  </MockWindow>

  上面四项全部能解释，才进入第 1 章。出现以下任一情况必须暂停：

  - VPS 资源不足，但扩容价格和能否降配不明；
  - 3000 被未知进程占用；
  - cloudflared 不健康或 Tunnel 负责人不明；
  - `chat.example.com` 已承载其他业务；
  - 模型接口、模型 ID、价格、余额或地区可用性无法确认；
  - 只有管理主密钥，无法创建独立 key；
  - 准备把 key 粘贴到聊天、仓库、截图或 shell 命令；
  - 准备用真实客户、工作秘密或个人敏感信息测试；
  - 不知道怎样停止模型费用或销毁不再使用的 VPS。

  本篇通过的成功状态不是“已经安装”，而是你能准确说出：谁负责页面、谁负责模型、数据会去哪里、费用在哪里停止，以及遇到什么情况必须先停。
</section>
