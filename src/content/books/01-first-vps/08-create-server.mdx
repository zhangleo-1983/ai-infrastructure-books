<section className="book-section" id="book01-ch8-firewall">
  ## 开始前：准备只允许 SSH 的云防火墙

  云防火墙是服务商在服务器外部提供的网络过滤规则。它决定哪些公网连接可以到达实例。第一册只需要 SSH 的 TCP 22 端口。

  TCP 是一种可靠传输协议；端口可以理解成服务器上不同网络服务的入口编号。OpenSSH 默认使用 TCP 22。

  <MockWindow title="Firewall Group · 教学仿真">
    <div slot="toolbar"><MockStatusBadge>最小规则</MockStatusBadge></div>
    <div className="mock-form-grid">
      <MockField label="Group Name">book01-ssh</MockField>
      <MockField label="Network">IPv4</MockField>
      <MockField label="Protocol">TCP</MockField>
      <MockField label="Port">22</MockField>
      <MockField label="Source">My IP / 你的当前公网 IP</MockField>
      <MockField label="Note">Allow SSH from my current network</MockField>
    </div>
  </MockWindow>

  做什么：

  1. 在 Vultr 控制台的 Network / Firewall 区域新建一个 Firewall Group；
  2. 名称使用 `book01-ssh` 这类不含个人信息的标签；
  3. 添加入站 IPv4 规则；
  4. 协议选择 TCP，端口填写 `22`；
  5. 来源优先选择 My IP，或填写你当前可信网络的公网 IP；
  6. 不添加其他入站端口；
  7. 保存后确认规则出现在列表中。

  为什么这样做：把来源限制为当前公网 IP，可以减少其他地址尝试连接 SSH。如果你的网络公网 IP 经常变化，原有规则可能会把你自己挡在外面。

  成功状态：防火墙组存在，唯一业务入站规则是你能解释的 TCP 22，来源是当前可信地址。

  失败判断：

  - 端口写成 20、21、222 或一个范围；
  - 同时开放了 80、443、面板端口或 All Ports；
  - 来源 IP 是服务器未来的 IP，而不是你当前上网网络的地址；
  - 防火墙组创建了，但没有在实例创建页选中。

  <Callout type="warning" title="动态公网 IP 的兼容分支">
    如果你的家庭宽带或移动网络频繁更换公网 IP，My IP 规则可能导致连接超时。兼容方案是只把 TCP 22 临时开放到 `0.0.0.0/0`，同时使用 SSH 密钥或强随机密码；登录成功后再收紧来源。`0.0.0.0/0` 表示所有 IPv4 来源，不是更安全的默认值。
  </Callout>
</section>

<section className="book-section" id="book01-ch8-step-1">
  ## 第一步：进入普通 Cloud Compute

  <InstructionStep number={1} title="打开 Products / Compute">
    登录 Vultr 官方控制台，进入 Products，再选择 Compute 和 Deploy。
  </InstructionStep>

  <InstructionStep number={2} title="实例类型选择 Shared CPU">
    不选择 Dedicated CPU、Cloud GPU、Bare Metal 或 Kubernetes。套餐分类使用能满足需求卡的普通 Cloud Compute / Shared CPU。
  </InstructionStep>

  为什么这样做：本书需要一台通用 Ubuntu VPS，不需要专用 CPU、GPU 或集群产品。

  成功状态：页面标题和选择摘要能看出这是 Shared CPU 云服务器。

  失败判断：页面要求选择 GPU 型号、裸金属配置或节点数量；产品价格明显偏离你的预算卡；返回上一级重新选择。
</section>

<section className="book-section" id="book01-ch8-step-2">
  ## 第二步：选择地区

  主线选择 Tokyo。东京不可用、缺少目标套餐，或你按第 5 章实测后决定使用备选时，选择 Los Angeles，并在交接卡中记录真实地区。

  为什么这样做：地区会影响库存、网络路径和后续排错。选择地区后，套餐列表可能重新加载。

  成功状态：

  - 创建摘要明确显示 Tokyo，或你已经记录的实际备选地区；
  - 该地区能继续选择符合需求卡的套餐；
  - 状态页没有尚未解释的相关故障。

  失败判断：

  - 只看到地图高亮，却没有确认城市名称；
  - 换了地区后，套餐配置或价格发生变化但没有重新核对；
  - 地区显示 Sold Out / Unavailable，仍反复点击。
</section>

<section className="book-section" id="book01-ch8-step-3">
  ## 第三步：选择满足下限的套餐

  在 Shared CPU 的套餐中，按第 3 章需求卡选择：

  <ComparisonTable>

  | 字段 | 通过条件 | 不通过时 |
  | --- | --- | --- |
  | vCPU | 至少 1 | 返回套餐列表 |
  | RAM | 至少 1 GB | 不选择 512 MB |
  | 系统盘 | 至少 25 GB | 不额外购买不明用途的块存储 |
  | Transfer | 至少 1 TB / 计费周期 | 查当前超额和计量规则 |
  | CPU 类型 | Shared CPU / 普通 Cloud Compute | 不选择专用或 GPU |
  | 持续价格 | 未超过预算停止线 | 不依赖促销后的临时价格 |

  </ComparisonTable>

  为什么这样做：这组下限用于第一册登录和第二册轻量服务。更大的套餐不会让你自动完成配置，只会增加持续费用。

  成功状态：五项资源和价格都能从当前套餐卡或结算摘要中找到。

  失败判断：只能看到营销名称；公网地址和传输规则不清楚；为了“以后可能有用”选择明显过大的配置。
</section>

<section className="book-section" id="book01-ch8-step-4">
  ## 第四步：只选择纯 Ubuntu 系统镜像

  在 Configure Software 或相近区域：

  1. 镜像类型选择 Operating System；
  2. 系统选择 Ubuntu；
  3. 版本选择 Ubuntu 24.04 LTS；
  4. 架构确认 x86_64、x64 或 amd64；
  5. 不选择 Marketplace Apps、ISO、Snapshot 或 Backup。

  <MockWindow title="Configure Software · 教学仿真">
    <div slot="toolbar"><MockStatusBadge>符合主线</MockStatusBadge></div>
    <div className="mock-form-grid">
      <MockField label="Image Type">Operating System</MockField>
      <MockField label="Operating System">Ubuntu</MockField>
      <MockField label="Version">24.04 LTS</MockField>
      <MockField label="Architecture">x64 / amd64</MockField>
      <MockField label="Marketplace App">None</MockField>
      <MockField label="Startup Script">None</MockField>
    </div>
  </MockWindow>

  为什么这样做：纯操作系统与第二册已经验收的 Ubuntu 命令一致。预装 WordPress、Docker、控制面板或其他 Marketplace App 会改变端口、账户和系统状态。

  成功状态：摘要只显示 Ubuntu 24.04 LTS x64，没有第三方应用。

  失败判断：系统卡片带有 WordPress、Docker、cPanel 或其他应用名称；选中了 ARM；页面显示从旧快照或备份恢复。
</section>

<section className="book-section" id="book01-ch8-step-5">
  ## 第五步：选择认证方式和管理员

  ### SSH 密钥主线

  在 Server Settings / SSH Keys 中，选中第 7 章添加的 `book01-my-computer` 公钥。核对名称和指纹，不要上传私钥。

  成功状态：创建摘要显示已选择一个你能辨认的 SSH Key。

  失败判断：列表为空；选中了旧电脑的密钥；要求粘贴的内容不是以 `ssh-ed25519` 开头的公钥。

  ### 密码完整路径

  如果不使用 SSH 密钥，确认当前镜像会生成管理员密码，并在实例创建后从官方控制台查看。不要提前把 Vultr 账户密码当成服务器密码。

  成功状态：你已经记录“密码认证”，并知道创建后必须从实例详情页取得随机密码。

  失败判断：既没有选 SSH Key，也无法确认服务器密码在哪里获得。

  ### 保持 root 主线

  第一版不启用 Limited User Login，以便默认管理员用户名保持 `root` 并衔接第二册。Limited User Login 会创建名为 `linuxuser` 的非 root 用户并授予 sudo 权限；它是可行的安全分支，但会改变用户名和部分命令写法。

  <Callout type="info" title="主线使用 root 是兼容性决定">
    长期运维通常应评估非 root 管理员、sudo 和限制直接 root 登录。第一册先让零基础读者完整验证一条与第二册一致的登录路径，后续安全章节再调整，不要在首次登录前同时改变多项认证设置。
  </Callout>
</section>

<section className="book-section" id="book01-ch8-step-6">
  ## 第六步：确认 Public IPv4

  在 Instance Connectivity 中：

  1. 选择 Instance(s) with Public IP；
  2. 确认 Public IPv4 已启用；
  3. 不选择 Private Instance behind NAT Gateway；
  4. IPv6 可以暂不启用，或者启用后仍必须保留 Public IPv4；
  5. 不要取消 Public IPv4。

  为什么这样做：第二册需要从公网直接使用服务器 IPv4。NAT Gateway、VPC 私网或 IPv6-only 都会改变操作路径。

  <MockWindow title="Instance Connectivity · 教学仿真">
    <div slot="toolbar"><MockStatusBadge>公网 IPv4 已启用</MockStatusBadge></div>
    <div className="mock-form-grid">
      <MockField label="Connectivity">Instance with Public IP</MockField>
      <MockField label="Public IPv4"><MockStatusBadge>Enabled</MockStatusBadge></MockField>
      <MockField label="Public IPv6">本书主线可不启用</MockField>
      <MockField label="NAT Gateway">Not selected</MockField>
    </div>
  </MockWindow>

  成功状态：当前摘要明确表示实例直接分配 Public IPv4。

  失败判断：只看到 VPC、Private、NAT、IPv6-only；或者 Public IPv4 复选框已经取消。
</section>

<section className="book-section" id="book01-ch8-step-7">
  ## 第七步：绑定防火墙，不提前开放第二册端口

  在 Firewall Group 中选择本章开头创建的 `book01-ssh`。

  为什么这样做：只有绑定到实例的防火墙组才会实际过滤流量。第一册仅验证 SSH，不需要面板端口、节点端口、HTTP 或 HTTPS。

  成功状态：创建摘要显示 `book01-ssh`，其中存在 TCP 22 规则。

  失败判断：防火墙组是 None；绑定了另一个包含 All Ports 的组；为了第二册提前开放多个未知端口。

  <Callout type="warning" title="第二册会在需要时增加端口">
    端口开放应跟随具体服务逐项完成。第一册不猜测 3X-UI 面板或节点最终使用的端口，也不把 TCP 与 UDP 混在一起开放。
  </Callout>
</section>

<section className="book-section" id="book01-ch8-step-8">
  ## 第八步：填写主机名和标签

  Hostname 是 Ubuntu 在网络中识别自己的名称；Label 是服务商控制台中帮助你辨认实例的标签。

  第一台练习服务器可以填写：

  - Server Hostname：`book01-vps`
  - Server Label：`book01-tokyo`

  如果实际选择洛杉矶，把标签改成 `book01-los-angeles`。

  不要在标签中写真实姓名、手机号、密码、用途敏感信息或客户名称。

  成功状态：两个名称简短、可辨认，不含空格和敏感信息，标签与实际地区一致。

  失败判断：名称仍是随机默认值而你有多台实例；标签写成密码；地区变化后没有更新标签。
</section>

<section className="book-section" id="book01-ch8-step-9">
  ## 第九步：逐项处理附加功能

  <ComparisonTable>

  | 功能 | 第一版选择 | 原因 |
  | --- | --- | --- |
  | Automatic Backups | 不启用 | 首次练习先保持费用可解释；不代表长期不需要备份 |
  | Snapshot / Backup image | 不选择 | 当前是全新系统，不从旧数据恢复 |
  | DDoS Protection | 不启用 | 不在首次轻量学习需求中，先核对费用与用途 |
  | Startup Script | 不填写 | 不在首次启动时自动执行未知命令 |
  | Cloud-Init User Data | 不填写 | 避免自动改变账户、SSH 或软件状态 |
  | VPC Network | 不额外创建 | 单台公网实例暂不需要私网互联 |
  | Auto Scaling / Load Balancer | 不添加 | 属于多实例架构，不是本书主线 |
  | Monitoring | 保留服务商基础状态能力 | 不安装额外代理或付费服务 |

  </ComparisonTable>

  <Callout type="danger" title="暂不购买备份，也必须接受数据丢失风险">
    这台服务器在首次学习阶段没有不可替代数据，所以主线先关闭自动备份。第二册配置稳定并开始长期使用后，应重新评估自动备份、快照和恢复演练。没有验证过恢复的备份，不能视为可靠保护。
  </Callout>
</section>

  逐项朗读摘要。如果任何一项与你真实页面不同，先解释差异，不要依靠“应该没问题”继续。

  成功状态：

  - 产品、地区、套餐、系统和架构全部符合需求卡；
  - Public IPv4 明确启用；
  - 认证方式有且只有你理解的选择；
  - 防火墙已绑定，并只为第一册准备 TCP 22；
  - 没有 Marketplace App、启动脚本和不明附加费用；
  - Deploy 尚未点击。

  失败判断：

  - 找不到 Ubuntu 24.04 LTS x64；
  - Public IPv4 不明确或已经关闭；
  - 选中了 ARM、NAT、应用镜像或恢复镜像；
  - SSH Key 与本地私钥不匹配；
  - 创建摘要出现无法解释的付费项；
  - 已经点击 Deploy，却还不知道持续费用。
