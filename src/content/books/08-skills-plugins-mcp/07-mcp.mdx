## MCP：连接 AI 与外部工具

MCP 是 Model Context Protocol 的缩写，中文可理解为“模型上下文协议”。它规定 AI 应用怎样发现并使用外部能力。协议统一了沟通方式，但不会自动保证服务器可信、权限合理或结果正确。

## 五个角色

```text
你
 ↓ 提出任务并决定权限
AI 应用（MCP 客户端）
 ↓ 通过 MCP 请求能力
MCP 服务器
 ↓ 调用工具或读取资源
本地文件 / 数据库 / 第三方服务
```

客户端是你正在使用的 AI 应用；服务器负责提供能力；工具执行动作；资源提供可读取内容；提示模板可以提供预设工作方法。具体服务器可能只实现其中一部分。

## 协议与信任要分开

“支持 MCP”只说明连接方式兼容。你仍需核对服务器来源、运行位置、它能看到的数据、调用的外部服务和更新方式。一个未知来源的本地服务器也可能读取文件或发起网络请求。

## 本地和远程连接

本地 MCP 服务器运行在自己的电脑或受控环境中，仍可能访问本机文件和网络。远程 MCP 服务器由外部服务运营，资料可能离开本机。两者都要检查数据边界，不能只用“本地”或“云端”判断安全。

## 画一张关系图

为准备试用的 MCP 写下：客户端名称、服务器来源、连接位置、提供的工具与资源、所需凭证、数据去向和撤销入口。任何一项未知，都标为待确认。

## 本章验收

成功状态是你能指出客户端、服务器、工具、资源、外部服务和数据流，并说明谁控制每一段。失败判断是把 MCP 当成单一软件、默认协议兼容等于安全可信，或说不清服务器实际运行在哪里。
