# 制作第一个个人 Skill

第一次制作 Skill，不要从自动发布或批量修改开始。选择已经手动成功三次、输入清楚、结果可立即检查的小任务，例如把会议记录整理成行动项草稿。

## 写一个最小结构

```text
名称：会议行动项整理
用途：从指定会议记录生成行动项草稿
适用：记录中已经包含事项和负责人
不适用：替负责人承诺日期、直接发送通知
输入：一份会议记录文件
输出：一份新的 Markdown 行动项表
步骤：回读事实 → 标记缺口 → 生成草稿 → 自查
停止条件：出现敏感资料、负责人或日期无法确认
```

这份结构与普通 Prompt 的区别在于，它会被重复使用，因此必须明确不适用场景和维护责任。

## 把变化内容留给当前任务

文件名、日期、参与者和保存位置不要写死在通用说明里。每次运行时单独提供。Skill 中只保留稳定规则，例如“未知负责人标记待确认”。

## 先人工模拟，再交给 AI

拿一份合成记录，按 Skill 步骤自己走一遍。检查每一步是否有足够输入、输出是否可验收、停止条件是否会真正触发。缺少哪一项，就先改说明。

## 用两个样例验证

第一个样例包含完整负责人和日期；第二个故意缺少负责人。合格 Skill 应在第一个生成完整表，在第二个标记待确认，而不是猜一个名字。

记录每次输出和问题。只修改一项说明后再次运行，确认改动没有破坏原来通过的样例。

## 版本与分享

在 Skill 顶部记录版本、校订日期和负责人。分享前删除真实数据与凭证，说明依赖的产品和工具。别人采用之前仍需在自己的权限环境中试用。

## 本章验收

成功状态是个人 Skill 有明确用途、不适用范围、输入、输出、步骤、停止条件和两个通过样例。失败判断是把一次聊天原样保存成 Skill，或包含真实凭证和无法复核的隐含背景。
