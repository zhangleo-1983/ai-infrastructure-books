## 组合多个能力但保持边界

组合扩展前画出数据流：谁读取什么，谁产生什么，谁接收下一步。能传摘要就不要传整份原文，能传字段就不要传整张表。

组合能力会把一个扩展的输出变成另一个扩展的输入。单独看都合理的权限，串起来后可能形成新的外部发送或数据累积。

## 用字段画数据流

```text
公开活动网页
  → 只读查询工具：标题、日期、地点
  → 整理 Skill：生成三字段摘要
  → 本地草稿文件：人工检查
```

如果下一步只需要标题、日期和地点，就不要传完整网页、访问日志或用户资料。

## 每条箭头写五项

| 项目 | 问题 |
| --- | --- |
| 发送者 | 哪个工具产生数据？ |
| 字段 | 具体传递哪些内容？ |
| 接收者 | 本地组件还是第三方服务？ |
| 用途 | 为什么完成下一步必须传？ |
| 保留 | 哪里会留下副本，多久清理？ |

不能回答的箭头先删除或改成人工转交。

## 为每一步设置独立权限

网页查询工具不需要写本地文件，整理 Skill 不需要登录外部账户，保存草稿的工具不需要发送消息。不要把“整个流程需要”误写成“每个组件都需要”。

## 在边界处人工检查

从外部资料进入本地、从本地结果准备对外发送、从只读转为写入时，都是适合设置停点的边界。先显示即将传出的字段，再决定是否继续。

## 组合后的故障隔离

记录每一步输入和输出的摘要。最终结果错误时，先找哪一步首次出现偏差，不要一次更换所有扩展。关闭下游写入，仍可在只读和草稿阶段排查。

## 本章验收

成功状态是每条数据流都有字段、目的、接收者、负责人和清理方式，各组件只拥有本步权限。失败判断是多个扩展互传完整资料，最终去向和错误起点都无法判断。
