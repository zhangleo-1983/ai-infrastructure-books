# 读懂并试用一个 Skill

Skill 可以理解为写给 AI 的可复用工作说明。它可能只包含一份指令文件，也可能带有模板、示例和辅助脚本。名字相同的 Skill 不一定来自同一发布者，安装前要阅读实际内容。

## 先回答五个问题

```text
目标：这个 Skill 帮助完成什么结果？
触发：什么任务应该使用，什么任务不该使用？
步骤：它要求 AI 按什么顺序工作？
工具：它会读取、修改、运行或连接什么？
停止：什么情况需要暂停并交给人处理？
```

如果说明只写“让 AI 更强”，却没有输入、输出和边界，就不能判断它是否适合当前任务。

## 阅读指令和关联文件

先找到 Skill 的主说明，再检查它引用的模板、脚本和配置。引用文件缺失时，AI 可能无法按说明完成任务；脚本来源不明时，不要运行。

把指令中的动作按风险标记为只读、创建新文件、修改现有文件、运行程序和外部动作。第一次试用只选择只读或创建可删除文件的路径。

## 使用合成资料试用

为“会议行动项整理 Skill”准备一份虚构会议记录。要求它只生成新文件，不发送消息、不访问其他目录。试用后对照 Skill 声明的步骤，检查实际读取和生成内容。

```text
请使用这个 Skill 处理 sample-meeting.txt。
只允许读取该文件并创建 output/tasks.md。
开始前列出计划，结束后列出实际使用的文件和未执行的动作。
```

## 记录适用与不适用

试用记录应写明版本、来源、输入、输出、权限、通过项和问题。若 Skill 只能在某个产品或目录结构中工作，也要写入限制。

## 本章验收

成功状态是你能解释 Skill 的目标、步骤、工具和停止条件，并用合成资料完成一次可撤回试用。失败判断是只看名称和介绍就安装，或未阅读关联脚本便允许运行。
