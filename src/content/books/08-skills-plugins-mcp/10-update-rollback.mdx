# 更新、兼容性与撤销

更新前保存版本、配置、权限和当前可用证据。先在低风险任务试用，再扩大范围。撤销时同时处理插件、连接、凭证和外部授权。

## 更新前建立基线

```text
扩展当前版本：
客户端当前版本：
配置与权限摘要：
通过的两个试用样例：
调用记录位置：
恢复旧版本或禁用方法：
```

基线不是备份秘密。配置文件包含凭证时，只记录安全保存位置，不把密文复制到普通文档。

## 阅读变化，不只点击更新

关注新增权限、数据去向、工具参数、最低客户端版本和弃用能力。更新说明不完整或要求突然扩大权限时，暂停并向发布者核实。

## 小范围回归

用更新前相同的合成资料，重复只读和草稿任务。比较工具清单、权限、输出、错误和调用次数。通过后再恢复真实但低风险的任务。

## 四层撤销

1. 在 AI 客户端禁用或卸载插件、Skill 或 MCP 配置；
2. 断开客户端连接；
3. 在外部服务撤销授权、令牌或应用访问；
4. 按规则清理本地配置、缓存和临时资料。

最后复测旧查询，确认无法再访问新数据。只删图标或配置文件并不能证明外部授权失效。

## 更新失败时

先停止写入和自动调用，保存错误与版本信息。能安全回退时恢复已验证版本；不能回退时保持禁用，并使用无扩展方案完成必要工作。

## 本章验收

成功状态是更新有基线、有相同样例回归，停用时四层都能完整退出。失败判断是自动更新后不复测，或只删除界面图标却保留有效令牌和外部授权。
