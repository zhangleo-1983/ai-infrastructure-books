# 数据与状态：先用假数据

假数据应该能覆盖正常、空、很长、重复和错误五种状态。它让你先检查界面和流程，不需要把真实客户资料接入尚未审查的代码。

## 假数据也要有设计

```text
正常：番茄、鸡蛋、面条
最少：番茄
空：空字符串
很长：重复食材和说明文字
重复：番茄、番茄、鸡蛋
特殊字符：番茄 <>& 鸡蛋
```

每组数据对应一个预期状态。最少输入是否允许，要由产品规则决定；原型不能悄悄猜测。

## 让演示数据明显是虚构的

使用“示例用户甲”“sample@example.invalid”等明确合成值，页面标注“演示数据”。不要用真实姓名稍作修改，也不要复制生产数据库的一小部分。

## 区分页面状态与长期保存

输入框当前文字属于页面状态；写入浏览器存储、文件或数据库属于持久保存。本册原型不需要长期保存。刷新后回到空状态，是有意的边界，不是缺陷。

## 写清清理方法

如果练习使用浏览器本地存储，提供清空按钮并说明怎样验证数据已消失。若没有保存，也在交接卡中写明“刷新后不保留”。

## 禁止把秘密伪装成假数据

测试 API Key、内部网址和真实账号仍然是敏感信息。使用无效占位符，并确保程序不会把它们误发到外部服务。

## 本章验收

成功状态是五种状态都有合成输入和预期结果，保存边界与清理方法清楚。失败判断是为了“更真实”复制生产数据，或页面暗中长期保存而项目简报没有说明。
