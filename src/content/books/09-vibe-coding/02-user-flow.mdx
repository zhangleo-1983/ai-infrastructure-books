# 从用户动作写页面

先写用户做什么，再决定需要哪些页面。最小路径通常是打开页面、输入内容、点击动作、看到结果和处理错误。

## 写一条主路径

```text
打开首页
→ 看到用途说明和食材输入框
→ 输入“番茄、鸡蛋、面条”
→ 点击“生成建议”
→ 看到三张晚餐建议卡
→ 点击“重新输入”回到输入状态
```

每个箭头都是用户能看到或执行的动作。不要写“系统智能处理”这种无法观察的中间步骤。

## 再写三条非理想路径

1. 输入为空：按钮不可用或点击后出现明确提示；
2. 只输入一个食材：说明至少需要几个，保留用户已输入内容；
3. 生成过程失败：显示可理解错误，并允许重试或返回。

错误路径也是产品的一部分。没有错误状态时，用户只能猜页面为什么没反应。

## 从动作推导页面，而不是反过来

本练习只需一个页面内的输入区、状态提示和结果区。不需要为了看起来完整增加“关于我们”“用户中心”和空导航。

## 为每个状态写进入和离开条件

| 状态 | 怎样进入 | 怎样离开 |
| --- | --- | --- |
| 空状态 | 首次打开或重新输入 | 填写有效食材 |
| 输入状态 | 用户开始输入 | 点击生成或清空 |
| 结果状态 | 生成成功 | 点击重新输入 |
| 错误状态 | 输入无效或处理失败 | 修正输入或重试 |

## 本章验收

成功状态是主路径和三条失败路径都能按用户动作复述，每个状态有进入和离开条件。失败判断是先堆导航和装饰，却说不清用户如何完成任务，或页面出错时没有恢复路径。
