# 先画界面，再决定技术

草图只要回答三件事：用户先看到什么、下一步点哪里、没有数据时显示什么。先解决信息层级，再让 AI 选择实现方式。

## 用文字方框画第一版

```text
┌──────────────────────────────┐
│ 晚餐灵感卡                   │
│ 输入手边的三种食材，查看搭配 │
│                              │
│ [ 番茄、鸡蛋、面条        ] │
│ [ 生成建议 ]                 │
│                              │
│ 状态或错误提示               │
│ [建议卡] [建议卡] [建议卡]   │
│ [重新输入]                   │
└──────────────────────────────┘
```

方框不需要颜色和精确尺寸。先确定标题、说明、输入、主要按钮、状态和结果的阅读顺序。

## 画出四种状态

空状态说明该输入什么；加载状态说明正在发生什么；结果状态展示建议；错误状态说明原因和恢复动作。把四张草图并排比较，确认页面不会在状态变化时突然失去标题或按钮。

## 按信息重要性排序

主要动作只有一个“生成建议”，视觉上应最明显。“重新输入”在结果出现后才需要，不应与主要按钮同时争夺注意。说明文字帮助用户完成任务，不放产品口号和无关功能。

## 手机优先检查

在窄纸条上重画草图。三张结果卡在手机上应纵向排列，按钮要能点，标题不能挤压输入。若窄屏无法解释，先改结构，不让 AI 用复杂 CSS 掩盖。

## 把草图交给 AI 前

用文字列出每块的用途和状态变化。AI 看图能力和界面工具会变化，文字说明是稳定的验收依据。

## 本章验收

成功状态是你能不用代码解释桌面和手机草图，四种状态都有内容与下一步。失败判断是从框架、组件和依赖名词开始，或只有漂亮首页截图却没有错误和结果状态。
