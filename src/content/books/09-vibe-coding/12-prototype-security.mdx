## 原型的隐私与安全边界

原型越容易分享，越容易被误认为正式服务。上线前先确定谁能访问、会收集什么、数据保存在哪里、如何删除，以及谁处理异常。

## 五项发布前检查

```text
访问：链接是本机、受限分享还是公开互联网？
数据：输入是否包含个人、客户或业务敏感信息？
秘密：密钥是否只在服务端安全环境中，未进入前端和仓库？
输入：用户内容是否会直接变成 HTML、文件路径或命令？
依赖：第三方服务会收到什么，适用什么条款和费用？
```

## 前端不是秘密存储位置

浏览器会下载前端代码。写进前端配置、页面脚本或公开仓库的 API Key 可能被任何访问者看到。需要秘密的功能应由受控服务端调用，并设置最小权限和使用限额。

## 假数据也要防止误用

页面明显标注“演示数据”，不要使用像真实身份证号、邮箱或客户记录的样例。提供一键清空或恢复演示数据的方法。

## 处理陌生输入

输入框可能收到空值、超长文本、脚本标签、特殊字符和重复提交。原型至少要限制长度、显示错误，不把用户输入直接执行为代码或命令。

## 公开前的停止条件

涉及真实付款、身份验证、医疗信息、未成年人数据、多人权限或长期保存时，停止自行公开，邀请专业开发与安全人员评审。

## 本章验收

成功状态是访问范围、数据、秘密、输入和第三方服务都有明确边界，演示数据可清理。失败判断是把本机可运行直接等同于可公开，或将密钥写进浏览器代码和仓库。
