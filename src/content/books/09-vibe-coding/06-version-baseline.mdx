## 版本、备份与恢复起点

Vibe coding 会快速产生多轮修改。如果没有可运行基线，页面出错时很难知道从哪里恢复。第一次改动前就保存一份能够启动和完成主要路径的版本。

## 什么是基线

基线包含项目文件、启动方法、假数据、通过的验收项和当前已知问题。它不只是压缩包或提交记录；没有验证过能运行的备份不能作为可靠恢复点。

```text
版本名称：prototype-01-baseline
启动方法：
主要路径：输入食材 → 点击生成 → 显示三条建议
通过检查：桌面、手机、空输入
已知问题：刷新后不保留结果
恢复方法：
```

## 使用版本工具或安全副本

代码项目优先使用 Git 等版本工具保存清晰变更。完全不熟悉版本工具时，可以先复制整个练习目录，并在副本上确认能启动。不要覆盖唯一副本。

保存前排除 `.env`、密钥、真实数据和体积很大的生成目录。备份位置也要符合组织的数据规则。

## 每轮只形成一个可解释版本

版本说明写“增加空输入提示”比“继续优化”更容易复核。修改后运行与该变化直接相关的检查，再保存新版本。多个无关功能不要混在一次改动里。

## 实际做一次恢复

在练习副本中做一个可撤回的小修改，然后恢复到基线并重新启动。成功状态应与基线记录一致。恢复从未演练过时，不能假定备份可用。

## 本章验收

成功状态是你拥有一个实际启动并验收过的基线，知道怎样查看变化和恢复。失败判断是只保存最后一份文件、备份含真实秘密，或恢复方法从未实际执行。
