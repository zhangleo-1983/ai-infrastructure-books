# 失败分类与根因分析

先分类再修复：资料缺失、任务理解错、推理或计算错、格式不符、工具失败、权限不足。不同类别需要不同的改动。

## 使用一致的失败标签

| 类别 | 例子 | 优先处理 |
| --- | --- | --- |
| 资料 | 原始说明缺少地点 | 补资料或保持未知 |
| 理解 | 把参加者清单写成宣传文 | 改目标与读者 |
| 事实/推理 | 改错日期或得出无依据结论 | 核对来源与推理步骤 |
| 格式 | 缺少指定字段 | 修输出协议 |
| 工具 | 查询超时或返回错误 | 查工具与外部状态 |
| 权限 | 无法读取或越界访问 | 修实际授权边界 |
| 评审 | 标准含糊导致判断不一致 | 校准评分指南 |

一个失败可以有多个标签，但先找最早出现偏差的环节。

## 写根因假设

```text
观察：C02 把缺失地点补成“社区中心”。
类别：资料缺口 + 事实编造。
假设：Prompt 没有规定未知项处理。
最小修复：增加“资料未说明时标为待确认”。
验证：只用 C02 和两个原通过样例回归。
```

根因是可以验证的解释，不是“模型不够聪明”。

## 一次只验证一个修复

同时换模型、Prompt、资料和工具，会让结果无法归因。先使用最小失败样例验证，再运行完整回归集。

## 记录未解决问题

无法稳定复现、缺少日志或需要专业判断时，保留“未知根因”，不要编造确定结论。必要时暂停相关任务范围。

## 本章验收

成功状态是失败有一致类别、最早偏差点、可验证假设和最小回归。失败判断是看到错误就更换所有组件，或把“模型随机”当成无需调查的最终原因。
