# 记录输入、输出和版本

没有版本记录，就无法解释结果变化。每次运行至少记录日期、输入编号、Prompt 版本、模型或工具版本、输出位置和人工结论。

## 一条运行记录

```text
运行编号：RUN-20260913-01
日期与时区：
测试集版本：cases-v1
样例编号：C01
Prompt 版本：prompt-v2
模型或产品标识：以当次界面或 API 返回为准
工具与连接版本：
输入位置：cases/C01.md
输出位置：runs/RUN-20260913-01/C01.md
耗时、调用与可见费用：
评审结论：
```

版本信息应来自实际界面、配置或返回值。产品没有显示精确版本时写“未提供”，不要凭记忆补写。

## 保存原始输出和评审分开

原始输出保持不改；人工标注和修订放在单独文件。直接在输出上改正确，会失去模型当时表现的证据。

## 记录环境变化

系统说明、项目资料、工具权限、检索来源和参数变化都可能影响结果。无法完整记录时，至少保存对任务有直接影响的设置和未知项。

## 保护评估记录

使用合成或批准的数据，日志中删除秘密和不必要的个人信息。共享前检查文件名、截图和错误堆栈是否泄露路径、账号或令牌。

## 本章验收

成功状态是从任一评审结论都能追溯到运行、输出、输入、Prompt 和测试集版本。失败判断是只保存最后截图、原始输出被覆盖，或记录中复制了真实敏感资料。
