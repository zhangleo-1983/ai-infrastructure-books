# 故障排查：结果不稳时改哪里

结果不稳时不要立刻把 Prompt 写长。先判断：目标是否含糊？资料是否缺失或冲突？约束是否互相矛盾？格式是否难以检查？步骤是否一次塞得太多？

## 五点调试顺序

| 检查位置 | 常见症状 | 优先修复 |
| --- | --- | --- |
| 目标与读者 | 内容方向经常跑偏 | 改写结果句 |
| 上下文 | 数字、名字、规则被编造 | 补资料或明确缺口 |
| 约束 | 长度、事实和语气互相冲突 | 排优先级，删除冲突 |
| 输出协议 | 遗漏难以发现 | 固定标题、字段和未知项 |
| 步骤 | 一次改太多，错误无法定位 | 拆成理解、计划、执行、评审 |

按照这个顺序，可以先解决影响最大的输入问题。不要先增加“你是世界顶级专家”等角色描述，它通常不能弥补资料缺失或验收标准空白。

## 保存最小复现

最小复现是一份能重复出现问题的最小任务包，包括 Prompt、必要资料、模型或产品名称、日期和问题输出。删掉无关聊天后问题仍会出现，才便于比较修复。

```text
问题：AI 每次都会增加“需要预约”。
事实来源：活动说明中没有预约信息。
当前 Prompt：请生成完整的行前清单。
期望：未说明的信息标为待确认。
实际：把“提前预约”写成确定要求。
```

从这里可以判断主要缺口在约束：Prompt 要求“完整”，却没有规定未知项如何处理。

## 一次只改一个变量

第一轮只加入：“原资料未说明的内容写为待确认，不得用常识补充。”其他资料、格式、模型和参数保持不变。运行两到三次，比较预约问题是否消失。

如果同时换模型、加示例、重写格式并增加资料，即使结果改善，也无法知道哪一项真正有效。

## 建立小型对照表

| 版本 | 唯一变化 | 结果 | 判断 |
| --- | --- | --- | --- |
| V1 | 基线 | 增加预约要求 | 未通过 |
| V2 | 新增未知项规则 | 预约列为待确认 | 通过 |
| V3 | 增加格式样例 | 结构更一致 | 保留 |

提示词不需要因为版本增加而无限变长。确认某条规则没有帮助后删除它，保留最短、可解释的有效版本。

## 判断是不是 Prompt 问题

工具没有读取文件、网页无法访问、权限不足、服务超时或源资料本身错误时，改 Prompt 不能解决根因。查看工具记录和原始资料，把技术故障与任务说明问题分开。

## 本章验收

成功状态是你能用最小复现说明问题，并指出哪一项修改带来了可重复变化。失败判断是连续叠加要求、同时更换多个条件，或用更长 Prompt 掩盖工具与资料故障。
