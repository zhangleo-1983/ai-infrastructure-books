# 附录：四张检查卡

把卡片复制到自己的文档中。每次只填写当前任务，不要把密码、验证码、API Key、私钥或真实客户资料存进通用模板。

## 任务输入卡

```text
目标与交付物：
读者与场景：
允许使用的资料：
限制与停止条件：
输出格式：
验收标准：
```

成功状态：另一个人仅阅读此卡，就能说出结果、读者、资料边界和完成标准。失败判断：仍需要从聊天历史猜测“到底要做什么”。

## 上下文摘要卡

```text
已确认事实：
已做决定：
仍待确认：
下一步：
不可触碰的边界：
```

建议在每个阶段结束时更新，并标明“由谁、在什么日期确认”。模型生成的摘要必须人工复核后才能作为下一阶段输入。

## 评审卡

```text
[ ] 每条关键结论都有来源
[ ] 没有把推断写成事实
[ ] 满足长度、语气和格式约束
[ ] 已列出无法判断的项目
[ ] 高风险动作仍由人确认
```

评审按“事实、完整性、约束、格式、语言”的顺序执行。前一层未通过时，先修复前一层。

## 工具闸门卡

```text
允许读取：
允许创建或修改：
禁止访问：
执行前需要展示：
必须暂停并等待人工处理：
执行后需要提供的证据：
撤回或恢复方法：
```

成功状态：实际产品权限和 Prompt 中的范围一致。失败判断：只在文字里要求“不要操作”，实际账户仍授予广泛写入或发送权限。

## Prompt 调试卡

```text
问题表现：
最小任务包：
期望结果：
实际结果：

[ ] 目标与读者是否明确
[ ] 上下文是否完整且无冲突
[ ] 约束是否可检查并有优先级
[ ] 输出结构是否暴露未知项
[ ] 任务是否需要拆分
[ ] 是否其实是资料、权限或工具故障

本轮只改变：
对照结果：
保留或撤销：
```

## 独立评审模板

```text
你的任务是评审，不是改写。

原始资料：
待评审结果：
验收标准：

请逐项输出：
- 结论：通过 / 未通过 / 无法判断
- 结果位置：
- 资料证据：
- 最小修复建议：

不要补充资料中不存在的事实，不要直接生成新版结果。
```

## 交接摘要模板

```text
任务目标：
最新交付物与位置：
已确认事实及来源：
已完成并通过的检查：
仍待确认：
已经否决、不要恢复的方案：
下一步只做：
权限收尾与恢复方法：
```
