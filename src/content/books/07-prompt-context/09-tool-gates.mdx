# 工具调用前的提示设计

涉及工具时，Prompt 要多写四件事：允许使用的资源、禁止触碰的资源、执行前预览、执行后证据。先读后写，先草稿后发送，先备份后删除。

工具可以是文件读写、网页浏览、命令运行、邮箱、日历或云盘连接器。Prompt 能说明操作边界，但真正的访问能力还受产品权限、系统权限和账户授权控制。两层都要检查。

## 四级工具闸门

| 级别 | 允许动作 | 适合阶段 |
| --- | --- | --- |
| 1. 只读 | 查看指定资料，不修改 | 理解和计划 |
| 2. 草稿 | 新建草稿，不覆盖原件、不发送 | 生成和预览 |
| 3. 有限修改 | 只修改已列明文件或记录 | 人工确认后的执行 |
| 4. 外部动作 | 发送、发布、删除、付款或授权 | 责任人逐项确认后 |

第一次任务停在第 2 级就够了。不要因为工具支持第 4 级，就默认让它使用全部能力。

## 一张可复制的工具闸门卡

```text
允许读取：activity.txt
允许创建：output/checklist.md
禁止访问：其他文件、邮箱、云盘和联系人
执行前：先展示计划和输出文件名
执行中：不得覆盖原文件，不得联网补充事实
执行后：列出实际读取和创建的文件，并展示内容供我检查
必须暂停：需要发送、发布、删除、登录、验证码或新增权限时
回滚方法：删除新建的 output/checklist.md
```

这张卡把“做什么”和“允许工具怎样做”分开。即使最终文字要求没有变化，换成能操作文件或外部服务的工具时，也要重新检查闸门。

## 权限提示不是安全锁

写下“不要读取其他文件”能帮助 AI 理解范围，但不能替代操作系统或产品权限。如果工具已经拥有整个云盘写权限，错误仍可能发生。能在设置中限制连接范围时，应使用实际权限限制；不能限制时，改用隔离练习资料或只读方式。

## 执行后索要证据

文件任务查看文件位置、修改差异和检查结果；网页任务查看最终页面与状态；发送任务查看草稿和收件人，并在真正发送后核对回执。AI 的一句“已完成”不构成证据。

```text
请不要总结过程。请列出：实际使用的资源、产生的变化、检查结果、
仍未执行的动作和恢复方法。无法提供证据的项目标为“未确认”。
```

## 本章验收

成功状态是工具动作有明确范围、执行前预览、执行后证据和回滚方式。失败判断是只写“请自动完成”，却没有实际权限限制和人工停点，或把“不要做”误认为系统一定无法做。
